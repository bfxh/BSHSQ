### 6. 收口检查后续（2026-09-14：T4 达标、T3 加量并定位、解算侧又否掉两个假说）

- **T4 ✅ 达标**：新增 `--example m1_islands`（碎片雨 12 000 体）——解算扩展
  **5.44×/8 线程**、总 tick 3.83×、串行/并行**末态哈希逐位一致** ⇒ 验收两项全过。
  「小岛 4/8 向量化批」这条 M1 路径**不必再做**（现有岛级并行即达标）。
- **T3 加量（−4%，逐位透明）**：盒对路径的体轴缓存（每体每帧 3 次旋转只算一次，
  与既有世界多面体缓存同机制）⇒ 8B 窄相 均 11.54 → **11.05**、峰 29.86 → **28.68**；
  两哈希逐位不变。**剩余 13% 在 M1 约束集内不可达**（详见 T3 节）。
- **解算侧否掉两个假说（负面结果记档）**：
  1. **「负载不均」不是 4.7×/8 的病因**：把岛分组从「按岛计数均分」改成
     **按工作量（岛内流形数）加权切分**（位透明：分组不参与逐岛计算），
     实测 解算 216.6 → **214.6ms（−1%，噪声）**、峰 502.9 → 501.7 ⇒ **回退**。
     原因：8B 的岛分布本就很均匀（22.5 万流形 / 10 万岛 ≈ 每岛 2.25）。
  2. **「窄相并行度差」是我上一轮的误读**：按同一 tick 窗口重测，窄相
     **1→8 线程 ≈ 3.2×**（36.85 → 11.54ms）、解算 ≈4.7×、查询 ≈3.7× ——
     都是访存受限场景的正常水平，无并行结构 bug。⇒ 解算/窄相的时间是
     **访存带宽 + 标量算术**的地板，M1 内（无 unsafe/SIMD）不可再压。
- **由此收敛**：M1 剩余的**性能类**验收（T2 宽相峰、T3 窄相峰）都已触到
  「无 unsafe/SIMD ⇒ 不可再压」的地板，**需与 V2 §11 核口径**；
  **功能类**只剩 T1（求解稳定/入睡）与它解锁的 T5 两列。

### 7. 解算相位的成本结构（2026-09-14 测量：iters 扫描，零改动）

`m1_scale 8 102400 100000 40 <iters>`，读「解算」列：

| iters | 解算 均 | 说明 |
|---|---|---|
| 4 | 38.5 ms | |
| 16 | 86.9 ms | 仓库当前配方 |
| 32 | 147.2 ms | |

线性拟合 ⇒ **固定成本 23.0 ms + 每次迭代 3.88 ms**（iters=16 时迭代占 **73%**、
固定占 27%）。三点几乎完美共线（残差 <1%）。

**推论（决定后续投入方向）**：
1. **固定部分（23ms）** = 建岛 + gather/scatter + 每岛约束构建 ⇒ 这一块「小岛批」
   能省，但对 8B 档天花板只有 27%（且实测按工作量加权重排分组 ≈0 收益，见 §6）。
2. **迭代部分（3.88ms/迭代）** = 逐点法向/摩擦求解。以 22.5 万接触点计，
   **≈138ns/点·迭代的 CPU** ≈ **2.6 ops/cycle 的标量算术**（不是访存黑洞、也不是
   每岛开销）⇒ 这一块**正是 SIMD 的靶子**（估 2-4×），且 GS 顺序在「**按岛批量**」
   （多条独立岛的约束并行推进）下**逐位不变** ⇒ 可行路径 = V2 §4.3/计划的
   「小岛 4/8 向量化批」（T4 原路径）——注意：它**不是**为 T4 的验收（已达标）
   而做，而是解算的**唯一 SIMD 入口**（岛内共享约束的 SIMD 会改 GS 序 = 改行为）。
3. **到 8B tick 目标的距离**：解算 = 23 + 16×3.88 = 85ms（40 tick 窗口）；
   即便算术全速 4×，也只剩 ~21ms ⇒ **单靠 SIMD 到不了「整 tick ≥30 FPS」**；
   要跨过去须动**迭代次数**（16 → 8 即省 31ms，但塔的稳定性研究说 16 是配方
   ⇒ 属物理取舍，需裁决）或**岛内并行**（用户已放开 unsafe；但 8B 岛仅 2.25 流形、
   岛级并行已 4.55–5.67×，岛内并行的空间在**更少更大岛**的场景里）。
4. **⚠️ 实施岛批量的前提（别直接开写）**：按点现取的标量数据（每点 ≈15 个 f32：   `ra/rb/t1/t2/nmass/tmass/cfm/pn/pt/rhs`…）在 4 lane 上是**分散**的 ⇒ 不先转
   **SoA 布局**，gather/scatter 会吃掉大部分 SIMD 收益。⇒ 正确顺序 =
   ① 约束数据 SoA 化（本次扫描已给出靶子：**每点·迭代 ≈138ns = 2.6 ops/cycle**）
   ② 再按岛批量 4 lane 推进（岛间独立 ⇒ 逐位不变，跨平台哈希门不需要放宽）。
   这与 T2 尾的「数据布局/局部性」是同一笔投入，不建议分两轮做。

6. **⚠️ 解算对「访存」比对「算术」更敏感（2026-09-14 实测，已回退）**：
   把 `group_apply` 里每点·迭代 4 次的 `Mat3::from_quat(rot)`（读四元数 16B、
   现算矩阵）改成**按帧缓存的世界旋转矩阵**（读 36B、免算）——**逐位透明**
   （`m0_gates` `0xfd70f215…` 不变、determinism PASS）但**实测退化 +11%**：
   解算 均 216.6 → **240.9ms**、峰 502.9 → 557.8。
   ⇒ 结论：**解算已到「访存延迟主导」**（36B 矩阵读取 > 16B 四元数读取的代价，
   远超省下的 ~30 flops）⇒ §7-2 里「138ns ≈ 2.6 ops/cycle ⇒ 算术主导」的推断
   **被本实验修正为偏乐观**。
   **对 SIMD 计划的影响（重要）**：岛批量 4-lane 若按 AoS 取数，会**放大**访存
   （4 lane 各自 36B+ ✓）⇒ 必须先做 **SoA 收缩**（把每点的 15 个 f32 按字段并成
   连续数组 ⇒ 4 lane 一次读 4 个同字段值 = 一条 16B ✓）**再**上 SIMD；
   顺序颠倒（先 SIMD 后布局）大概率白做。

7. **⚠️ 「4 岛轮转交错」（岛批量）实测失败：结果与逐岛不同，且机制未查明（2026-09-14，已回退）**
   ——**这是本轮最重要的负面结果，下一轮做 SIMD 前必须先解决它**。

   做法（三步，每步都以四段哈希为预言机）：① 把单点求解从 `solve_constraint`
   内层原样抽成 `solve_point`（纯搬运）——**哈希不变 ✅**；② 把「逐岛 build→warm→
   迭代→收集」改成「整组 build→整组 warm→逐岛迭代→逐岛收集」（约束背靠背入
   `cbuf` + 每岛区间）——**哈希不变 ✅**；③ 在 ② 之上做 4 lane 轮转（每 lane 一条
   岛链，按 (it, shock, c) 游标推进，方向规则与逐岛逐字一致）——**哈希变了 ❌**：
   `0xfd70f215…` → `0xf23ae81a…`（stress `0x696a25bc…` → `0xb77f61b2…`），
   且**是结构性发散而非 ULP**：门槛场景 p50 0.46 → **2.78ms**、末态活跃 **0 → 38**
   （不再入睡）、8B stress p50 285 → 298。

   **已排除**：① 记账（`LANES=1` 退化时哈希**正确** ⇒ lane 游标/方向/计数无误）；
   ② 岛间重叠——**已用断言验证岛间体集合确实不相交**（`local_of` 二次写入即 panic，
   实测未触发）⇒「岛间独立 ⇒ 交错透明」这一前提**在数据上成立，但结果仍不同**。

   **✅ 判定实验（已完成，2026-09-14）：岛间确实无耦合。** 把**逐岛处理顺序整体
   颠倒**（`for &ii in awake.iter().rev()`，仅此一处改动）⇒ `m0_gates` 哈希
   `0xfd70f215…` **逐位不变**（stress `0x696a25bc…` 同样不变）⇒
   **「岛间独立」在行为上成立**（与断言的数据独立互为印证）⇒
   **上一轮交错版的差异必来自 lane 代码本身的 bug**（≈100 行游标逻辑），
   **不是可选路径的语义障碍**。「4 岛轮转 / 岛批量」路线**未被否定**，
   只是那一版实现有错 —— 下一步只需审/重写那 100 行并逐帧对拍调用序即可。
   顺带记一条纪律：**这类判定不必先写 lane 机**——颠倒一个既有循环（两行）就能
   把「语义不成立」与「实现有 bug」分开，成本差两个数量级。

   **✅ 已定位并修好、且已实测无收益（2026-09-14，最终回退）**：
   - **根因（自检一击命中）**：lane 的**「相位耗尽判定放在了步进之后」**——最后一次
     主迭代只把 `it` 递增到 `iters`，并不置 `done`，于是下一次进入时又按 shock 路径
     多执行**一整轮 `rev=true` 的逆序扫掠**。自检打印：`lane 步数 17/期望 16
     （nc=1 iters=16 shock=0）`。这解释了全部症状（过度反向扫掠 ⇒ 不收敛、p50 5×）。
   - **修法**：把「`nc == 0 || (it >= iters && shock >= shock_iterations)`」提到
     **步进之前**置 `done`。
   - **修后**：**四处哈希逐位回到基线**（`0xfd70f215…` / `0x696a25bc…` / determinism /
     T4 碎片雨）⇒ **4 岛轮转是逐位透明的**（自检通过、末态入睡恢复、p50 0.454）。
   - **但实测无收益**：8B 解算 均 216.6 → **223.0ms**、峰 502.9 → 526.3（**−3%**，
     含 run-to-run 噪声；T4 扩展 5.69× 不变）⇒ 每步的游标分支开销 ≥ 交错带来的
     ILP/局部性收益（访存延迟已由 OOO 在岛内/岛间自行重叠）。
   ⇒ **「岛批量交错」路线实测关闭**（不是"未验证"，而是"等价且无加速"）；
     §7-4 里「岛批量是解算唯一 SIMD 入口、估 2–4×」的预期**被本轮证伪**。
     解算若要提速，剩下的是**同岛内 4 点 4-lane**（Jacobi 化 = 改行为，属 (a) 类）
     或 **SoA + 单岛向量化**（不靠交错）。两条都须先量化再开工。

8. **解算 SIMD 的「先量化」结论（2026-09-14）：剩余两条路的上界都很低，不建议开工。**
   - **同岛内 4 点 4-lane**：lane 宽度受流形点数限制——实测点数直方图
     （125 体复现）`[1点:140 / 2点:146 / 3点:18 / 4点:200]`，**均值 2.52 点/流形**，
     只有 **40%** 的流形能填满 4 lane ⇒ 即使向量化零开销，上界也只有「点求解占比
     （73%）× 可填满比例（≈40%）」≈ **≤30% 的解算**；而它还要付 (a) 类行为变化
     （Jacobi 化，需重跑金样容差表 + 三哈希）与 gather/scatter（已实测这类
     访存代价可观：矩阵缓存那次 +11%）⇒ **净收益大概率 ≤10%**，不值得 ~400 行。
   - **SoA + 单岛向量化**：单点算术只有 3 个分量 ⇒ 4 lane 里 1 个恒闲（3/4 利用率），
     且 SoA 的收益属于「降访存」，而本轮已实测解算虽是访存敏感、但**扁平化
     （= 同类布局改动）净收益 −0.4%**（§7-5）⇒ 单独做同样量级。
   - **⇒ 解算在 M1 结构内的 SIMD 路已穷尽**（岛级并行 5.1–5.7×、6 条候选全部实测/
     量化完毕）。真要再降，只剩**改物理**（迭代次数 16 → 8，省约 31ms/tick，
     但塔的稳定性研究说 16 是配方）——那是产品取舍，不是工程优化。
   **下一轮的正确顺序**：先在**最小复现**上（`diag_min` 5×5×5 或 col45）逐岛打印
   `solve_constraint` 的调用序 + `pn/pt` 快照，与逐岛版逐帧对拍，**找到差异那一行**
   再谈 SIMD；或者直接改用「同岛内 4 点 4-lane」（同岛、同一约束的 4 个点做 4 lane
   ——但那是 Jacobi 化 = 改行为，需按 (a) 处理）。
   **配方余料**（30 分钟可重做）：`solve_point` 抽取 + 约束背靠背 + 每岛区间 +
   `collect_warm` 助手 + 轮转游标；这三步的代码形态与验证结果都在本条。

5. **已验证「①单独做没用」（2026-09-14，已回退）**：把「每约束一个
   `Vec<PointConstraint>`」扁平化成「组内一个点数组 + 约束带区间」
   （`ConstraintBatch { constraints, points }`，接口按 `pt_start/pt_len` 取切片）——
   **逐位透明**（`m0_gates` `0xfd70f215…` 不变、41 项测试全绿、workspace 编译 0 警告）
   但**实测无收益**：解算 均 216.6 → **215.8ms（−0.4%，噪声）**、峰 502.9 → 506.9。
   ⇒ 原因：约束点本就连续且 cbuf 跨帧复用（没有逐帧分配可省）⇒ **扁平化只有与
   ②的 SIMD 同批做才有意义**（本仓纪律：无收益不引入 ⇒ 已回退）。改动配方记档：
   `ConstraintBatch{constraints, points}` + `pt_start/pt_len` + 求解循环用
   `let ConstraintBatch { constraints, points } = cbuf;` 解构避开借用冲突。


### 8. T1 泵治理第二段：回退匹配「深度跳变门」落地（2026-09-14）

**入口**（OPEN-PROBLEMS P1 候选①，用户选定）：给回退（特征未命中）分支加**非距离**
判别式。距离类门已两轮实测失效（有害/必需匹配同在 1×skin 内）。

**第一版踩坑（方法论级教训，记档）**：把门写成「有效深度（`depth0 + sep·n`）与
本帧裁剪深度之差 ≤ 阈值」⇒ **零效果、dE 逐位不变（148.9）**。根因：锚点随体刚性
移动时 `depth0 + sep·n ≡ cp.depth` **恒成立**（实测差 ≤1e-6）⇒ 那是恒真式，
**不是判别式**。教训：加门之前先验证判据在数据上有方差（本轮靠插桩才发现）。

**插桩实测（本轮新增，落地前已删）**：在回退匹配接受处打印
`d / d0 / dd / r / pn / pt`（限行数 + 抽样）。拿到两类真实信号：
1. **瞬态型（t≈5–10）**：锚点在**分离态**烘焙（`d0 = −3.7mm`）后被拿去**触地帧**用
   （`d = +0.2mm`）⇒ **深度跳变 dd ≈ 3.9mm**、且携带加载相冲量 `pn ≈ 13`；
2. **极限环型（t>30）**：dd 小（µm 级）但携带**贴锥**的切向冲量（`|pt| = μ·pn`
   分毫不差，如 9.76 vs 9.83）——箱在滑动，冲量在锥极限。

**正确形式 = `|cp.depth − w.depth0| ≤ 阈值`**（直接量跳变，别绕有效深度）。
**阈值扫描（125 体复现 dE 峰值）**：1mm → 63.8、0.5mm → 27.8、
**0.25mm → 18.2（取此档：验收线 ≤20）**、0.1mm → 17.7（更紧开始逼近全拒；
全拒 = 16.2 但塔崩）。物理含义：`dd ≈ v·dt` ⇒ 只对「深度变化快于 ~1.5 cm/s」的
接触拒配，与睡眠阈（4 cm/s）同量级；塔的承重腿（持续正深度、慢变）不受影响。

**290.8**（同会话）⇒ **无收益、略负** ⇒ **回退**。

**推论（记档，防重走）**：扫掠的访存大头**不在点自身的数据**，而在 `bodies` 侧
（每点每次扫掠要做 `inv_mass` 读 + 世界惯性张量应用 ×2 体）。而 bodies 侧的缓存
路已在 §7-6 被否（世界旋转矩阵缓存 **+11%** 退化）⇒ **「解算访存」这一条线到此
穷尽**：点布局（本轮）、体侧缓存（§7-6）、扁平化（§7-5）、快速哈希（§12）、
预取（W8）**五路全否** ⇒ 只剩「减少工作单元数」（聚类裁点）或「改变算术形态」
（SIMD，上界已量 ≤10%）两类，且都不足以独立跨过 9× 缺口。

### 16. warm 槽位表落地（2026-09-14 第十三段）：8B 总 tick −34.8ms（−9.9%），逐位不变

**动机与分拆**（§12 遗留 + DESIGN §11）：`warm 合并 + 剪枝` 33.5ms/tick 的大头是
**散列桶访存**（先证「印章法替代 binary_search」无收益 ⇒ 不是查找算法的问题）。

**落地 = 稠密槽位表**：`warm_slots: Vec<(键, WarmManifold)>`（连续内存）+
`warm_index: HashMap<键, u32>`（只存 u32 槽号）+ `warm_free`（空洞 LIFO 复用）。
- 查找：索引给槽号，数据在稠密槽位（`build_constraint` 带槽号进约束）；
- 回写：**按槽号原位写**（零哈希）；
- 剪枝：对稠密槽位**单遍顺序扫** + 印章判定（等价性见 §DESIGN §11：有流形且≥1 体
  清醒 ⇒ 必属清醒岛 ⇒ 必被求解盖章；双睡条目两规则都保）。

**同机背靠背 A/B（8B 120 tick，iters=16）**：

|---|---|---|
| 哈希表（原） | **351.2** | **309.4** |
| **槽位表（落地）** | **316.4** | **275.8** |
| 差 | **−34.8ms（−9.9%）** | −33.6ms（−10.9%） |

**逐位不变**：`m0_gates` `0xbdf0cee6…` ✓、determinism `0x8142fe05…` ✓、

**剩余（下一步）**：泄漏探针实测「被替换旧值的释放 churn」另值 **≈11-14ms/tick**

### 17. 点数据扁平 arena（2026-09-14 第十四段）：**尝试后回退**（不变量 bug），配方与判据记档

**动机**（§16 残余）：泄漏探针实测「被替换旧值的释放 churn」≈11.4ms/tick——
`WarmManifold.points: Vec<WarmPoint>` 每 tick 22 万次小 Vec 分配+释放。

**实现（已回退）**：`WarmManifold` 改为 `{normal, points_off: u32, points_len: u8, seen}`
（无堆）；点数据进**扁平 arena**（双缓冲 `warm_points` / `warm_points_scratch`，
容量跨 tick 复用）；收集直写**分组 arena**、合并时顺序拼接并重基 offset；
保留条目（双睡）数据搬进新 arena 并重写 offset。

**实测**：8B 总均 **298.6**（vs 槽位表版 316.4，**−17.8ms**）、解算均 257.5 ⇒ 收益真实，
**但 m0_gates 压力场景在 tick ~60 后 panic**：`range start index 138435 out of range
for slice of length 138184`。诊断探针（打印 slot/off/len/键/seen）显示坏槽
**`seen` 陈旧（=60，即本调用未刷新）却仍在索引里**，且 offset 超出当前 arena
⇒ **「键→槽唯一性」不变量被破坏**（同一键出现两个槽：索引指向其一，另一槽的
`offset` 停在旧 arena 上；剪枝时 `index.remove(key)` 只摘掉索引的那一个）。

**下一步的正确做法（重做时按此）**：
1. 在 merge 末尾加**不变量自检**（debug 断言/测试）：对每个索引键
   `warm_slots[index[key]].0 == key && seen == stamp`；对每个活槽
   `points_off + points_len <= arena.len()`；
2. 排查「同键双槽」的产生点——最可能是**同一调用内同键出现两次**
   （两处 `warm_outs` 条目都看到 `slot == u32::MAX` 各分配一次）或
   `warm_free` 与旧索引的交互；修法优先「写入前先查索引（同键复用它已有的槽）」；
3. 用 `m0_gates`（两个场景）+ 8B + 金样三场景判定；逐位不变是硬要求。
**当前状态**：槽位表（§16）已落地且稳（−9.9%、逐位不变）；arena 属**未完成项**。

### 18. warm 点数据**定长内联**落地（2026-09-14 第十五段）：总 tick 再 −17.7ms（−5.6%）

**承接 §17**：arena 方案收益真实（−17.8ms）但有「键→槽唯一性」bug。改走**更小的等效修法**：
`WarmManifold.points: Vec<WarmPoint>` → **`[WarmPoint; 4] + n: u8`**（流形点 ≤4，
窄相已截断）——彻底去堆、零逐条分配/释放，且**不需要 arena/offset/双缓冲**
（无新不变量 ⇒ 无新 bug 面）。

|---|---|---|
| 槽位表（§16） | 316.4 | 275.8 |
