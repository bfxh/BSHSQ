#### K.1 成因拆解（同轮追加）：**78% 是"面选择变化"，但它解释不了 §9 的崩**

做法：特征 ID 是位域（bit31 = 入射侧 A/B、bit30 = 裁剪交点 vs 顶点、其余 = 几何哈希），
把"回退命中"的那对特征异或后按位域拆开 ⇒ 直接读出变了哪一种（`feature_kind` /
`feature_hash_part`，诊断、三哈希不变）。

| 场景（占该场景的**回退命中**） | 侧别翻转 | 裁剪路变 | **哈希变** | 特征相同 |
|---|---|---|---|---|
| tower25 | 21.5% | 22.7% | **55.9%** | 0.0% |
| pyramid（--steps 600） | 37.6% | 14.9% | **47.2%** | 0.4% |

⇒ 塔的失配里 **78%（= 侧别 21.5% + 哈希 55.9%）是"接触仍在、但面选择变了"**
（参考面在 A/B 间跳，或盒内参考面索引/入射面变）；22.7% 是"裁剪交点 ↔ 入射面顶点"互换。
"特征相同"≈0 说明这些回退**从不因顺序/距离门误入**（都是真的换了编码）。

**⚠️ 这条读数的边界（推翻本节的初读）**：以上都是**跨帧** churn（每帧重检测时面选择会变）。
而 §9 的 P1 在**一个 tick 内复用同一张流形表** ⇒ 特征 ID 逐子步完全相同 ⇒ warm 匹配是
**精确命中**、暖启动完整。⇒ **特征 churn 解释不了 §9 的崩溃**，本节初稿提出的
"参考面翻转导致复用不稳"**被削弱**；反而加强了候选机理①（**开局自由落体的检测冻结**：
塔前 ~100 tick 在落体，一 tick 下坠 2–5 cm，后 3 个子步用接触前流形 ⇒ 深穿透无阻挡）。

**仍然有信息量的那一半**：在**常规路径**（每子步重检测）上，塔每个子步有 30% 的点拿不到
精确暖启动（18.7% 走收紧的回退、11.7% 完全没匹配）。收紧回退是历史上**故意**的
（放宽到 4×skin 会错配锚点 ⇒ 暖冲量过驱动 ⇒ 堆永不入睡），所以这里没有"放宽就好"的余地；
**剩下待查的是那 11.7% 完全未匹配的拒因**（三个回退门的哪一个 + "无上一帧流形"），
这才是"塔的暖启动为什么比平面堆差"的最后一环。

**原提案（保留，K.1 之后成为唯一候选）**：§9 的 P1 若重开，配"运动自适应检测节奏"
（准静态每 tick 一次、`max|v|·dt > skin` 时加测）——动机是塔开局自由落体（2 cm 缝，
一 tick 下坠 2–5 cm）时"子步 0 检测、后续复用"会让后 3 个子步用**接触前**的流形
⇒ 深穿透无阻挡 ⇒ 巨额修正。**这条仍未验证**（K.1 已把"参考面翻转"那个竞争候选削弱：
tick 内复用流形时特征 ID 不变）。

### L. §9 的 P1 重测（检测每步一次）——崩可复现，但**崩因不是 warm 匹配**；运动自适应给出权衡曲线

**动机（先查档，再动手）**：`git show 00a1ebf --stat` 显示那次 P1 实验**只改了两份文档**
（`DESIGN-staged-solver.md` +40、`EXPERIMENTS.md` +1）——**实现从未入档**（工作区做完即回退），
所以「塔崩 |v| 44.4 ⇒ 廉价子步不成立」这条结论**事后无法复核**；而本会话已两次修正

**当前位姿**重算深度/锚点、warm 表改稠密槽位、A3 按组紧凑（热路径与 `BodySet` 解耦）。

2. 复用的真实代价落在**慢动/沉降期**：`0.5·skin` 阈值仍放行了塔的蠕动（|v|≈0.2–0.3）⇒

3. **方法论**：否证实验的**实现不入档**会让结论无法复核——本会话两次修正 §9/§10 的归因
   都撞上这一点。建议今后否证实验至少把补丁留成 `git stash`/分支或写进 EXPERIMENTS 的
   附录（一行 `git diff` 即可）。

### M. 「检测每步一次」的崩因坐实＝**检测视野不足**（skin 扫描，零代码判别）

**假设（承接 L）**：复用流形时真正缺的是"**逼近中的接触**"——盒子以 v 逼近，`v·dt_tick`
那段距离必须在本 tick 内被拦住，但窄相只在 `sep ≤ skin` 时才产流形。
**判别（纯配置、零代码）**：加大 skin ⇒ 视野覆盖 `v·dt`（0.6 m/s ⇒ 10 mm @60 Hz）。

| tower25 @300，检测每步一次 | \|v\|max | KE | y 带 | 最深 |
|---|---|---|---|---|
| skin=0.01（原） | 14.619 | 299 134 | [0.24,12.18] | 0.140 |
| skin=0.02 | 1.959 | **2 386（÷125）** | [0.25,12.15] ✓ | 0.016 |
| skin=0.04 | 0.598 | 1 992 | [0.25,12.18] ✓ | 0.018 |
| skin=0.08 | **0.321** | 1 271 | [0.25,12.19] ✓ | 0.025 |

⇒ **假设成立**：加大视野即可让"检测每步一次"在塔上**不崩**；`skin=0.08` 时 |v|max 0.321
与基线 0.305 同量级（KE 仍 1.4×，即复用仍留有代价）。
⇒ **2026-09-14 的"塔崩 ⇒ 检测冻结不可行"应改写**为「**检测视野与检测节奏不匹配**」：
视野 10 mm = `v·dt` 10 mm（0.6 m/s 逼近）⇒ 逼近段完全没被覆盖。
⇒ 顺带解释了历史上一处表面矛盾（"skin 0.02 在**每子步检测**下更差"）：**视野的最优值
取决于检测节奏**——每子步检测时 `dt_detect` 小、小视野最优；每 tick 检测时视野必须覆盖
`v·dt_tick`。

**下一步设计（未实现，机制已由本表背书）**：视野不该是常数，应为
`skin + max(0, v_接近)·dt_detect`（**速度充气视野**）：
- 每子步检测 ⇒ `dt_detect` 小 ⇒ 视野自动小 ⇒ 保持基线的塔最优（skin 0.01）；
- 每 tick 检测 ⇒ 视野自动放大 ⇒ 不漏逼近接触；
- **不需要额外机制**：本仓求解器已有 spec 项（`sep·inv_dt`）负责"允许多快闭合"，
  视野放大后的接触会被平滑拦停（这正是 skin=0.02/0.04/0.08 三档不崩且越大约稳的原因）。
实现面：`narrow.collide` 需多传 `dt`（`bodies` 已在手，相对速度可读）；判据
`d <= skin` → `d <= skin + max(0, −v_rel·n)·dt`。判定 = 塔三场景 + 125 体 + 三哈希换代 +
arena 长跑 `--steps 3000`（默认档唯一有效的门）。

### N. 速度充气视野落地：把「检测每步一次」的崩**修掉了**（skin 保持 0.01）

**实现**（`DefaultNarrowPhase::set_predict_dt`，由 `World` 每子步设为**检测间隔**）：
窄相接受判据从 `sep ≤ skin` 放宽为 `sep ≤ skin + max(0, v_接近)·predict_dt`
（`v_接近` 取质心相对速度在法向的投影；角项忽略，贴面接触上是一阶小量）。
两处 SAT 预筛（盒对 + 多面体对）与 `clip` 的逐点过滤共用本对的充气量（scratch 字段）。
- **复用流形时** `predict_dt = dt_tick`（视野覆盖到下一次检测）；
- **每子步检测时恒传 0** ⇒ 现行行为**逐位不变**（三哈希已验证）；
- CCD 逐采样显式清零（它在时间维上已走路径，不叠加预测）。

**判定（tower25 @300，skin 保持 0.01）**：

| 配置 | \|v\|max | KE | y 带 |
|---|---|---|---|
| 基线（每子步检测） | 0.305 | 905 | [0.25,12.15] |
| 检测每步一次（**无**充气） | 14.619 | **299 134** | [0.24,12.18] |
| **检测每步一次 + 充气视野** | **0.279** | **1 078** | [0.25,12.14] ✓ |
| 同上 + stab=2 | 0.379 | 1 023 | [0.25,12.18] ✓ |

⇒ **崩被修掉**：同是"检测每步一次"，KE 从 30 万降到 **1 078**（÷280）。且比"整体加大 skin"
更有效（skin=0.02/0.04/0.08 三档的 KE 是 2 386/1 992/1 271）——符合设计意图：
**只在真正逼近处放大视野**，而不是全局抬高接受门限（后者会改稳态行为）。

**其它场景（同开关开启）**：

| 判据 | 基线 | 检测每步一次 + 充气 |
|---|---|---|
| pyramid p50 | 1.03–1.07 ms | **0.982 ms** |
| pyramid 宽相 + 窄相 | 295 µs | **155 µs** |
| pyramid 求解 | 918 µs | 850 µs（早退更早触发：匹配更稳 ⇒ 收敛更快） |
| pyramid 末态动能 Σv² | 1.1064 | 1.3537（+22%） |
| 125 体 末态 KE / \|ω\| | 1.6 / 0.132 | **0.5（好 3 倍）/ 0.052** |

**判定**：机制成立、代价从"崩"降到"塔 KE ×1.2–1.7"，**但仍不是默认档**（塔是 T1 验收
主靶，KE 仍高 20–70%）⇒ 与 `stabilization_iterations` 同类处置：**默认关、按需开、留档**。
`detect_once_per_tick` 保持 `false`（关闭态三哈希逐位一致）。
**意义**：DESIGN §9/§10 的"廉价子步不可行"至此**被三层修正**——① 归因（配对/暖启动）被
实测排除（末节 L）；② 机理是检测视野不足（末节 M）；③ **修复落地后崩消失**（本节）。
⇒ 「检测每步一次」从"否证"变回"**有代价的可行档**"，剩下的差距是塔那 20–70% 的 KE——
候选收窄到"陈旧接触集"的最后一环（spec 额度每子步重发 / 接触点的世界位置陈旧）。

### O. 复用模式「放宽回退匹配半径」——否证（余价不来自未匹配点的冻结几何）

**假设（承接 N 的余价）**：复用流形时那 3–8% 未匹配点的接触几何被**冻结在世界点上**
（`clip` 产出的世界点逐子步被重新锚定、不随体移动）⇒ 力臂/深度在错位置求值，是塔
KE ×1.2–1.7 的来源。而"回退半径收紧到 1×skin"是为**跨帧重检测**调的（防面选择 churn
造成错配，K.1），tick 内复用无此 churn（K.1 实测精确 92–96.6%）⇒ 放宽应当安全且有效。

**做法**：`ImpulseSolver::set_loose_warm(reuse)`（只在复用模式生效；关闭时逐位不变），
回退接受半径 `match_dist·0.25` → `match_dist`（单变量）。

| 配置（复用 + 充气视野） | 回退收紧（现行） | **回退放宽** |
|---|---|---|
| tower25 stab=0 KE | 1 078 | **1 451（更差）** |
| tower25 stab=0 \|v\|max | 0.279 | 0.376 |
| tower25 stab=2 KE | 1 023 | 1 193 |
| pyramid p50 | **0.982 ms** | 1.101 ms |
| pyramid 末态动能 Σv² | 1.3537 | **1.0220（比基线 1.1064 还好）** |
| 125 体 KE | 0.5 | 0.5 |

⇒ **假设不成立**：放宽回退使塔更差（KE +35%）而金字塔的时序也变差（放宽 ⇒ 更多锚点被继承
⇒ 早退更晚触发？或匹配分支更贵）——净收益为负 ⇒ **不采纳，代码已回退**（工作区与
`20919d7` 逐位一致）。
⇒ 复用余价的来源**仍未定位**；剩下的候选：① spec 额度在复用下的发放语义（本仓 `depth`
每子步从锚点重算 ⇒ 理论上自洽，未实测）；② 冻结的**点集**本身（少点/多点）在迭代中的
累积效应；③ 复用与无偏置末趟（stab）的交互（stab=2 时余价从 ×1.2 升到 ×1.7）。

### Q. 两个指定任务同时收口：复用余价「不重要」、A6「前提不成立」（2026-09-20 续）

#### Q.1 复用余价的机理——两个候选都否证，且它本来就不影响决策

新落地解算记账（`solve_accounting_take`：点总数 / 分离点数 / `spec` 和 / `bias` 和；
零行为影响）。tower25 @300（substeps=4、stab=0）：

| 记账 | 检测关（基线） | 检测开（复用+充气） |
|---|---|---|
| 点总数 | 1529 万 | 1534 万（+0.3%） |
| 分离点占比（吃 spec） | 24.9% | 25.3% |
| **spec 和** | 5 805 069 | 5 853 291（+0.8%） |
| **bias 和** | 65 500 | 61 694（**−5.8%**） |
| warm 精确率 | 69.6% | **76.1%** |
| 末态 KE | 905 | 1 078（+19%） |

⇒ ① **"复用让去穿透/闭合额度被重复发放"否证**（三个量都在 ±1% 内，bias 反而更低）；
② "复用让暖启动变差"此前已否证（精确率反而更高）；③ 末节 P 已证**复用根本不省塔的时间**

### R. 胶囊体浏览器穿地：机制定位到"静止时向下漂移"（2026-09-20 续）

**机制（轨迹读数）**：e>0 时胶囊**先正确落定在 y≈0.69**，然后**以越来越快的速度下沉**

（即某个偏置的方向反了），e>0 只是让残余抖动使它**保持清醒**从而暴露出来。

**教训**：`e>0` 是**暴露器**（保持清醒），不是病因；单测的材质要跟真实场景一致。

**下一步（入口已就绪）**：用 `capsule_probe.rs`（一条命令、确定性）调试——
① 先确认**偏置方向**：打印该接触的 `depth`/法线/`rhs`（加临时探针）；
② 怀疑面：胶囊 arm 里 `depth`/`point` 与求解器约定的接缝（窄相自测过的那几项**不足以**
证明求解器看到的约定一致）；③ 修好后 `capsule_drop.rs` 的材质要改成 μ=0.7/e=0.05

#### R.1 根因锁定：**EPA 跑在"光滑支撑"上不适定**；修法＝圆角内核化（2026-09-20 续）

**判据（把接触细节打出来）**：引擎级重现（`capsule_drop.rs`，μ=0.7/e=0.05）逐 tick 打印
法线与**带符号**深度，落地瞬间的读数：

| tick | y | vy | 流形 | 法线 | 深度 max |
|---|---|---|---|---|---|
| 57 | 0.6977 | +0.477 | 1 | `[0, 1, 0]` ✓ | 0.0063 ✓（正确落定） |
| 58–60 | 0.70 | ≈0 | 1 | `[0,1,0]` ✓ | −0.001…−0.007 ✓（贴面，正常） |

⇒ ① **落定本身是对的**（t=57 深度 0.0063、法线向上 ✓）；② 病态出现在**贴着接触的临界
时刻**：法线退化成 **45° 对角**（= 大盒的**角点方向**）、深度虚高到 **42 m**（≈ 30·√2）。

**为什么是 EPA（两个独立证据）**：
1. 42 这个量级不是任何深度，而是**支撑平面在角点上的投影**（大盒半长 30 ⇒ 对角投影 30√2）；
2. 我把该路径改成"用 EPA 的深度"后，**窄相单测反而挂了一个** ⇒ 临界接触一旦交给 EPA
   就不可靠；两条实验性改动（见证点平面、EPA 深度）**已回退**（窄相 2 单测恢复全绿）。

**根因（原理）**：`gjk::epa` 的多面体展开假定**支撑体有多面体面片**；而我的
`CapsuleSupport` 是**光滑曲面**（支撑点随方向连续滑动、没有平面片）⇒ 对这类支撑 EPA
**不适定**（面法线/终止判据都退化）。**这是"圆角形状直接喂 EPA"的经典陷阱。**

**修法（已定方向，未实现）＝圆角内核化（rounded-shape core decomposition）**：
让 GJK 跑**线段内核**（不含量半径），得到"线段 ↔ 对方"的**距离与见证点**（良态、纯多面体）；
再把半径**解析加回**：接触判据 `d_seg < radius + skin`、压入量 `radius − d_seg`、
逐端点深度用**见证点平面**（`n·p_other`，注意**不能**用对方的支撑平面——大盒 + 微倾法线
会给出数十米的偏移，这正是本节的 42）。⇒ EPA 只在"线段**进入**对方"时才会被调用（罕见且
良态）。**归一化约定仍是 a→b，且必须用两体中心定号**（穿透时见证点会换序）。

**当前状态**：窄相 2 单测全绿（回退后）；`capsule_drop.rs` 仍是 **ignored 重现**
（失败模式：落定正确但随后正反馈下沉）；浏览器接线**未恢复**（arena 保持 15/4/0）。
本节与 R 合起来构成下一轮"一条命令开工"的完整入口：修 `capsule_reach`（内核化）→ 解禁
`capsule_drop.rs` → 重接线 → 自检应 16/3/0。

## R.2 内核化**两次实现都失败**——并牵出更根本的 GJK 缺陷（2026-09-20）

按 R.1 的方向动手，两次尝试都留下**硬读数**，且都指向同一个根因：

**(a) 零半径线段芯**（新增 `gjk::SegmentSupport`，不含量半径）——用例
`capsule_vs_box_floor_vertical`（盒地板顶面 y=0；胶囊下端点在 y=0.29、真压入 1 cm）实测：

    [DBG core-sep] d=7.077  p_a=(0, 0.29, 0)  p_b=(5, 0, 5)  n=(-0.7065, +0.0410, -0.7065)

真值应为 `d=0.29 / p_b=(0, 0, 0)`（顶面）。返回的 `p_b` 是**盒角**，`d` 正是到该角点的距离
（‖(5,0,5) − (0,0.29,0)‖ = 7.077 ✓ 自洽）⇒ 法线成了 45° 对角。

**(b) 微量半径芯**（`radius = 1e-3` 的 `CapsuleSupport`，本意是避开退化）——**同样失败**，
读数只在小数末位变化（`0.706517` vs `0.70651287`）⇒ 证明问题**不在芯的退化**。

**根因（本节真正的发现，范围超出胶囊）**：本仓 `gjk::gjk` 在**对方支撑出现"面平局"**时
（盒顶面对 `dir = ±Y` 的支撑：四个角点并列）会把支撑点解到**同一个角点**，随后的迭代
"无进展 ⇒ 提前退出"，返回**角点见证 + 虚高距离**。圆角胶囊平时看着正常，是因为光滑支撑恒有
**唯一**支撑点，把平局掩盖了；一旦换成任何"点状/线段状"支撑（零半径与微量半径都一样），
平局立刻显形 ⇒ **"收成芯再跑 GJK"这条修法整体否证**（两次实现、两条读数）。

**由此定下的下一步（方向已换，锚点已找到）**：**不要在相交支里用 GJK/EPA 定法线**，改走本仓
**已有的解析最近点**——`sphere_convex_ab`（`lib.rs:1157`）用
`closest_point_on_poly(&self.poly_b, center)` 配 `inside` / `max_plane_d_of` 处理内部情形，
**没有 GJK、没有 EPA、没有平局**。胶囊接触按其分解：对中心线取最近点（端点起步，再
`p ← 段上最近点(q)` / `q ← poly 上最近点(p)` 迭代 2–4 次，每步只复用 `closest_point_on_poly`），
半径解析加回；逐端点深度沿用现有 `radius − n·(s − p_other)`——该式只用到 `n·p_other`＝**平面
常数**，不依赖见证点的切向位置（这正是 (a)(b) 里 `p_b` 取到角点却仍能算对深度的原因）。
顺手可加一道廉栅：EPA 荒谬深度闸（`!depth.is_finite() || depth > 1e3·radius ⇒ None`），
宁可当帧无接触，也别灌入 42 m 压入量把刚体打穿地面。

## R.3 解析最近点落地：胶囊穿地缺陷关闭，arena 15/4/0 → 16/3/0（2026-09-20）

按 R.2 的路线实现并全链验证（本条是**结论**，实现细节留在代码注释里）：

**改动两处**
1. 新增 `capsule_axis_reach`（`lib.rs`，紧邻 `sphere_convex_ab`）：中心线取最近点——迭代
   `q ← closest_point_on_poly(p)`、`p ← 段上最近点(q)`（≤4 轮；点到**凸**集的距离沿线段是
   凸函数 ⇒ 驻点即全局最近点对），再把采样点交给球的解析路径拿对方**表面点**。
2. 两条胶囊臂：对方是**多面体**（`poly_for` 命中）走上面的解析路；否则（胶囊/球/高度场）
   退回原 GJK 路。压入量公式两路统一改为**见证点平面** `plane = n·p_other`。

**为什么"支撑平面"必须换掉**（R.1 里那个 42 的真正出口）：`n·support(对方, ∓n)` 对**光滑**体
（球/胶囊）恰好等于表面点投影 ⇒ 精确；对**多面体**取的是**最远点**投影——大盒配微倾法线就是
±30 量级的偏移。而 `n·p_other`（真表面点）对两类都精确 ⇒ 一条公式通吃。

**判据读数（全部可复现）**
- 窄相 `cargo test --release -p vxl-phys-narrow`：**30/30**（含 `capsule_vs_box_floor_vertical`
  与 `capsule_flat_gives_two_points` 两单测）；
- `capsule_drop.rs` **解除 ignore** 转常开回归门：静置段 `y=0.7000` **恒定**（= 半高 0.4 +
  半径 0.3）、法线精确 `(0,1,0)`、`vy=0`；接触建立于 t=57（深度 6.3 mm）、6 帧内收敛；
- 浏览器 arena 自检：`vxl-phys 15/4/0 → 16/3/0`（**降级 4→3**：胶囊探针不再走
  `capsule→凸包` 回退）；9 引擎矩阵**失败项 0**。

**接线**（都在 `physarena` 仓）：`src/engines/vxl.ts` 能力表加 `capsule` + 桥声明
`vxl_add_capsule` + 分发 case + 其体积式（质量可比性）；桥 `vxl_add_capsule` 本就是导出 ✓。

**方法论留档**（三轮踩坑的共同教训）：**"光滑外形直接喂 EPA"与"退化支撑喂 GJK"是同一枚
硬币的两面**——EPA 要面片、GJK 要非退化；胶囊的线段芯两边都不满足。稳妥解法是**别让窄相
走这两条泛型路**，改用形状自身的解析量（球/胶囊各有最近的解析例程）。

### 第三轮实测（同日）：找到缺的那个机制 —— 但**未落地**（留给下一个会话）

> ⚠️ **语义更正（写档时自查发现，重要）**：下面实测的**不是"时间滞回"**（跨子步连续 N 次），
> 而是"**接触数门**"。原因：我那段临时实现的计数器声明在 `solve_phase` **函数内部**，而
> `solve_phase` 是**每次（子步 × 趟）调用一次** ⇒ 计数器每次调用都从零开始 ⇒ 实际语义 =
> **"同一次 `solve_phase` 内、同一睡体累计 ≥K 条 hot 接触观测才唤醒"**（一个睡体被 1–2 个
> 抖动的清醒邻居碰时**不醒**，被 ≥K 个**同时**在动的邻居围住才醒）。
> ⇒ **读数属于"接触数门"变体**；**"时间滞回"变体（跨子步累加）尚未测**，两者语义不同、
> 落地前应各测一遍。
> ⚠️ **实现警告**：若把该计数器从 `solve_phase` 内部挪到**持久状态**（省一次 Vec 分配），
> 语义会**变成跨子步累积**、下面这组读数**不再适用** ⇒ 要保读数就保持"每调用清零"；
> 要试时间滞回就**另设**计数器/常量，别改这个的寿命。

`vxl-phys-solver` 的 `SUBISLAND_SLEEP` 唤醒分支，20 行临时改动：唤醒需**同一次 `solve_phase` 内
累计 ≥`K` 条 hot 接触**（`hot` = 相对速度 > `SUBISLAND_WAKE_MULT × sleep_linear` 或角速超阈）。

| 配置（场景同上，600 tick） | 末态 awake | 缺口体 | **wake 率（<1 过）** | 快速体 | \|v\|max | 尾窗 p50 |
|---|---|---|---|---|---|---|
| K=0（现行）+ shock2 + stab2 | 9979 | 8314 | **1.40 ❌** | 0 | 0.200 | 609 ms |
| **K=8（=2 tick）单独** | 9541 | 8594 | **0.20 ✅（5× 余量）** | **1** | **0.267** | 303 ms |
| **K=8 + shock2 + stab2** | —（见趋势） | **5987** | **0.20 ✅** | 0 | 0.212 | 498 ms |

**关键不是静态读数，是趋势**：`K=8 + shock2 + stab2` 的 awake 在窗口内**单调加速下降**
（tick 100→500：9798 → 9501 → 9121 → 8609 → 8060；每 100 tick 降 **−300 → −550**），
而**同配置 K=0 是卡住不降的**（9979 / 直方图 4650 集中在 0.04–0.08）⇒
**滞回正是缺的那个机制**：它止住了近阈 churn，堆才真的开始静下来。

**⇒ 外推：window ≈1400–1600 tick 应达 awake→0**（判据本身允许"指定 tick 前入睡"；
⚠️ 是**外推**不是实测——600 tick 窗口内没到 0，落地时必须用长窗口确认）。
而且它**同时**松开了另外两条判据的余量（wake 率 5×、弹射归零）⇒ 与 shock/stab 不再互斥。

**为什么本轮不落地**（写给下一个会话）：它会**广泛改变睡眠行为**（塔/默认档/金样/规模档的冻结值
都要按 ADR-0004 换代），而一次完整落地 = 调 K + 负面检查（唤醒迟滞对"该醒"场景的影响）
+ 四哈希/金样/规模档换代 + 长窗口确认，属"独立立项"而不是顺手拧。**代码改动在这里**：

```rust
// crates/vxl-phys-solver/src/lib.rs，`solve_phase` 内的 SUBISLAND_SLEEP 唤醒分支
//（⚠️ 计数器**必须留在 `solve_phase` 内**才能复现上面那组读数；挪到持久状态 = 换语义）：
// const WAKE_STREAK_K: u32 = 8;   // 0 = 关闭 = 现行行为（须走直通分支；照 P7 滤波的教训）
// let mut wake_streak: Vec<u32> = vec![0; bodies.len()];   // 每次 solve_phase 调用清零
let hot = rel > SUBISLAND_WAKE_MULT * config.sleep_linear
    || bodies.angvel(w).length() > SUBISLAND_WAKE_MULT * config.sleep_angular;
if hot {
    wake_streak[s] = wake_streak[s].saturating_add(1);
    if wake_streak[s] >= WAKE_STREAK_K { bodies.awake[s] = true; bodies.sleep_timer[s] = 0.0; wake_streak[s] = 0; }
} else {
    wake_streak[s] = 0;
}
```

### 第五轮（同日）：**判据 3 达成** —— 准静态"安座"趟（`settled_hold_iterations`）

上节的门把 wake 率与沉降都拉动了，但 `awake→0` 渐近不达（2600 tick 时仍 1661）。本轮的机制
直接打**残差的来源**：

**诊断**：残余速度面状卡在睡眠阈的 1–4 倍，而**每子步的重力增量就是 `g·sub_dt ≈ 0.041 m/s`**
（`substeps 4`）——**睡眠阈 0.04 与它同量级** ⇒ 静止体只要求解器没把重力**完全**抵消，
就永远够不着阈值（这与 `SESSION-2026-09-18-SLEEP.md` §1C 的"残余由子步分辨率决定"是同一件事的
另一面）。

**机制**：主迭代与 shock 之后，对**准静态接触**（法向相对速度 `|vn| < 4×sleep_linear`）
做 `N` 遍**精确法向归零**（`λ = −vn·m_eff`，逐点有效质量与主迭代同一套组内缓存）；
**只动法向、不动切向** ⇒ 不改变摩擦/滑动语义；`|vn|` 大的（真撞击/真分离）一概不碰。

**两条实现纪律（第一版栽过，务必照抄）**：
1. **不动 `p.pn`**：warm 缓存必须只装"求解器自己的冲量"；掺入外来冲量会污染下一子步的
   暖启动 ⇒ 实测**爆掉**（6152 快体、\|v\|max 81、深穿透 347 tick）。
2. **欠松弛 ω = 0.25**：流形 ≤4 点是**冗余**约束，逐点各自"精确归零"会叠加
   （×点数 ×趟数 ×子步数）⇒ 过冲。

**读数**（`m1_pile`；配方 = `iters 16 / substeps 4 / threads 8 / shock 2 / stab 2 / wakeK 8`）：

| 配置 | **入睡 tick** | 末态 awake | 缺口 | 快速 | 深穿透 tick | 尾窗 p50 |
|---|---|---|---|---|---|---|
| 门档（hold 0） | 未入睡 | 7491 | 5734 | 0 | 0 | 292 ms |
| hold 2 | 未入睡 | **10**（差一点） | — | — | 0 | 1.44 ms |
| **hold 4** | **387** | **0 ✅** | **0** | 0 | **0** | **0.174 ms** |
| sub8 + hold 4 | **120** | **0 ✅** | 0 | 0 | 0 | 0.346 ms |

⇒ **判据 3 三项全达成**：① `awake→0`（**tick 387 入睡**，窗口内）② 末态 `deep = 0` 且深穿透 0 tick
③ 稳态 p50 **0.17 ms**（基线 292 ms）。**这条把 `M1-EXIT.md` §2.2 的 ❌ 变成 ✅。**

**安全侧（都过）**：`sleep_wake_contract` 扩展两组 —— ① **唤醒侧**：`hold ∈ {2, 4}` 下睡体被
3 m/s 撞**仍然醒且被推动**（tick 9 / Δx 0.14 m，与开关关闭时一致）；② **确定性**：开两个开关
两跑**逐位一致**（位置+速度 bits）。

**默认仍关**（`settled_hold_iterations: 0`）⇒ 身份不变（门槛 `0x6536fa72…`、压力 `0x417be20a…`、
`determinism` `0x711be572…`、默认档 4 冻结值、金样三门全不动）。**验收走配方**
（`... 16 4 8 600 2 2 8 4`）——与"保真档配方"同一条路数。

⚠️ **诚实标注**：这条趟会去掉**接触对上 <0.16 m/s 的法向运动**（= 把"准静态微动"钉住），
所以它是**为稳态服务**的机制；对"缓慢沉降/颗粒蠕流"类场景语义上会**略微提前冻住**。

## 2026-10-09 · `e = 1` 弹跳耗散：**否证"调参可修"** + 根因定位 + 零换代修复

**假设（外部评审给的归因）**：`e = 1` 的碰撞每次损失约 27% 机械能，原因是软接触参数

**方法**：在 `bench/realism-probe` 的 R2 场景上做参数扫描（阻尼比 / 接触频率 / 子步×迭代 /
修正速度钳制），看**首次反弹顶点的能量保留率**。

**结果（release）**：

| 档位 | 首弹能量保留 |
|---|---|
| 默认（freq 30/60，ζ=10，2×3） | 0.7247 |
| ζ = 0 | **2.20 → 8.48（能量增长，不稳定）** |
| ζ = 0.1 / 0.5 / 1 / 2 / 5 / 20 | 0.51 / 0.55 / 0.59 / 0.64 / 0.69 / 0.74（非单调） |
| static_freq 10 / 30 / 120 / 240 | 0.52 / 0.68 / 0.75 / 0.76（无一接近 1） |
| **4×8（substeps×iters）** | **0.0557** |
| **8×16** | **0.0000** |
| max_corrective_velocity 1 / 3 / 10 / 100 | 0.7247（**完全无影响**） |

**裁决**：❌ **"调某个参数就能修"被否证** —— 响应非单调、且方向相反（降低阻尼反而注入能量），
而**迭代越多耗散越彻底**。

**根因（读码定位）**：`soft_contact` 的右端项 `rhs = bias − spec + bounce`，其中
`spec = max(−depth,0)/dt` 是 speculative 接触的"允许接近速度"；`bounce` 用**每子步重算**的 `vn`，

**修法**：`rhs = bias + if bounce > 0 { bounce } else { bounce - spec }` —— 有回弹意图时
不扣接近预算。`bounce == 0`（默认档 e = 0）与原式浮点等价。

**验收**：默认档首弹 **0.7247 → 0.9531**；4×8 **0.0557 → 0.9010**；8×16 **0.0000 → 0.7889**。

### R9：冲击破坏**与子步数无关**（2026-10-10，修一处真缺陷）

**怎么发现**：给评审「方向 10」的真实性半边（破坏事件触发精度）写探针时，按解析预测
（12 m/s 弹体从 0.8 m 外撞体素块，投机皮肤带 0.02 m ⇒ 第 4 个 tick 该撞上）**一次都没触发**。

**定位（读码 + 三条对照实验）**：

1. 打印 t=1..8 的 `impacts()`：t=4（几何刚好接触）**没记录**；t=5 记录到 `approach = 0.168`
   ——**不是 12**。`record_impacts` 是**每子步 `clear` 重记**的，`step()` 之后看到的是
   **最后一个子步**的快照；而快撞在**第 1 个子步就被求解器解掉**（法向速度归零）⇒ 末子步
   只剩 ~0.17 m/s。
2. **`substeps = 1` 对照**：同一场景记录到 `approach = 12.000`，且**挖出 108 块碎块**。
   ⇒ 破坏结果**取决于子步数**，而 `substeps` 只是积分细分，不该改变"撞上了没有"。
3. 阈值降到 0.1 后 2 子步档也能挖出（60 块）⇒ 确认只是"记录值被覆盖"，不是挖不动。

**为什么既有测试没抓到**：`mesh_carve.rs::impact_carves_wall_and_spawns_debris` 走默认 2 子步、
12 m/s、阈值 3.0，**是过的**——它的弹体起点让撞击正好落在**最后一个子步**（记录没被覆盖）。
把起点挪半个子步（`-3.0 → -3.05`）**仍然过** ⇒ 不是简单奇偶，是"撞击相位恰好没被覆盖"的侥幸。
这类"靠场景相位侥幸通过"的判据，正是 R9 要换成**显式对照两档子步**的理由。

**修法**：`record_impacts` 从"每子步重记"改成**按 tick 合并**——首子步清空、其余子步对同一
`(provider, body)` 只留**接近速度最大**的一条（并列留先出现的；顺序 = 首次出现序 ⇒ 确定性）。
每条记录的速度仍是**该子步解算前**的值（原修复要绕开的"读末态速度"病仍然绕开）。

**读数（R9 探针；关重力、弹体 12 m/s、阈值 5.0、120 tick）**：

|---|---|---|
| 解析预测 | 5 | — |
| 默认（2 子步）· **修前** | **未触发** | **0** |
| 默认（2 子步）· 修后 | **5** | **108** |

**验收**：`gate_bench.sh` R9 四条（解析 ±1 / 两档子步逐值相同 / 都挖得出 / 亚阈为 0）；

## 静置叠体（睡眠不了的根因 = 接触面**相对偏航**；2026-10-15）

**动机**：门槛档（`m0_gates` 的 `max_wake_flips` 档）稳态永远有 ~10 个体醒着，
P19 / P20 两笔改动都被它顶红。上一轮探针只打 `|v|`，读成「悬在阈值下沿的**接触闪烁极限环**」
——**这一条是错的**：睡眠判据是**与门**（`|v| < sleep_linear` **且** `|ω| < sleep_angular`
才累加计时器，见 `sleep_pass_island`），`|v|` 全在阈下**本该入睡**。

**方法**：`m0_flip_forensics` 加第二轴读数（`|ω|` + 判据分类 + 唤醒归因），再用
`min` 子命令做最小复现。**结果（门槛档 600 tick）**：醒着 10 个中 `|v|` p50/p90/max =
**0.0129 / 0.0317 / 0.0375**（阈 0.04 之下）、`|ω|` = **0.1043 / 0.1446 / 0.1454**（阈 0.05 的
2–3 倍）；148 次翻转的唤醒归因 = 强撞直通 91 / 线性 hot 30 / **角速 hot 22** / 无来源 5，
角速 hot 来源榜 = 体 10271（8 次）…；末窗里体 10491 **完全静止**（`|v|=|ω|=0`）却每 ~61 tick
被 10271 唤醒。**裁决**：**✅ 归因改挂 `|ω|` 轴**，岛级唤醒语义仍正确、源头在角速轴。

### 最小复现 = 两个平放立方体，只差「相对偏航」（30 行，`m0_flip_forensics min`）

场景：64 块静态瓷砖（x 3..=10 / z 8..=15，`(x, 0.5, z)`、half 0.5）+ 两个 0.8 m 立方体
（half 0.4 / 密度 1000）叠在瓷砖正中：底体心 `(7, 1.4, 12)`、顶体心 `(7, 2.2, 12)`
（静置面 y = 1.0 ⇒ **零缝、零沉入、零初速**）。**唯一变量** = 底体绕竖直轴的偏航（顶体不偏航）。

| 变量 | 读数（默认档，`min` 3000 tick） | 裁决 |
|---|---|---|
| 相对偏航 **0°** | 计时器清零 **2/3000**、末窗 `|ω|` **0**、bias 记账 0.01/帧 | 面重合 ⇒ **入睡** |
| 相对偏航 **0.2°** | 清零 464/3000、末窗 `|ω|` 0.0006 | **入睡**（阈值之下） |
| 相对偏航 **0.5°** | 清零 2985/3000、末窗 `|ω|` 0.12 | **永不入睡** |
| 相对偏航 **1 / 3 / 6.1 / 45°** | 清零 ≥2985/3000、末窗 `|ω|` 0.13–0.18、bias 记账 572–1431/帧 | **永不入睡**（分水岭在 0.2°–0.5°） |
| 相对偏航 **90°** | 清零 **2/3000**、末窗 `|ω|` **0** | **入睡** ⇒ 是「面错开」，不是「角度大小」（正方形面对 90° 自映射） |
| 6.1°，跑 **6000 tick** | 末窗 `|ω|` 0.171 / 0.142，`y` 在 3000→6000 tick 之间不动 | **不衰减**（100 s 无趋势） |
| 6.1°，`maxcorr=0` | 立刻入睡、bias 记账 → **0**，但堆体下沉 `y` 1.40 → 1.09（−30 cm） | **只是归因，不是修法** |
| 6.1°，`sbase=1`（底体换成**静态**同尺寸盒） | 清零 2833/3000、末窗 `|ω|` 0.06、仍醒 | 不需要「两个动态体」，**只需要错开的面** |
| 对照：偏航盒**单**坐在 1 m 瓷砖上（接触流形 = 盒自身底面） | 清零 2/3000、bias 记账 0 | **入睡** ⇒ 大平面上的偏航盒没事 |

**三条旧口径就地作废**：①「两个轴对齐盒叠放就够」✗（`min 0` 实测会睡）；②「底体倾斜是根因」✗
——把门槛档那对的实位姿代回去：四元数 = 绕 x 转 90.1° ∘ 小幅偏差，而**立方体对 90° 旋转对称**
⇒ 有效姿态是「**平放 + 偏航 6.1°**」，根本没有倾角；再用干净单轴倾角 4°/6.06° 配同样的
40 mm 角点埋深重建，照样入睡；③「接触闪烁极限环」✗（`|v|` 阈下、清零计时器的是 `|ω|`）。

**载体 = 去穿透偏置速度**（`constraint.rs::soft_contact` 的 `erp·(depth−slop)`，经速度通道留在
最终速度里，而 `solve` 内的 `sleep_pass` 读的正是这份速度）：偏航时底体稳态保持 **6 mm** 埋深
（> `linear_slop` 5 mm）⇒ `bias` 恒不为 0（记账 `bias×1000 ≈ 660/帧`、`spec` 腿 ≈ 0）；
`maxcorr=0` 归零偏置即入睡（但下沉）⇒ 因果链干净。

### 修法候选（最小对 / 全场景 3000 tick 最大单体贴翻转率）

| 旋钮 | 最小对（相对偏航 6.1°，3000 tick） | 全场景门槛档（3000 tick） | 裁决 |
|---|---|---|---|
| 默认 `3 iters / 2 substeps / stab 0 / hold 0` | 清零 2998/3000、末窗 `|ω|` 0.176 / 0.143 | 最大单体贴 48 次 ⇒ **0.960/s**（闸 `<1.0`，只剩 4% 余量） | 贴边过 |
| `substeps=4` | **仍醒**（清零 2899/3000、`|ω|` 0.084） | 最大 3 次 ⇒ **0.060/s** | ⚠️ 全场景有效、**最小对不够** |
| `substeps=8` | **入睡**（清零 5/3000、`τ` 峰值 0.502） | 未测长时程 | ✅ 最小对也收干净 |
| `hold=4`（安座趟） | 入睡（清零 406/3000、带 2 次翻转） | 未测 | ✅ |
| `iters=16` | 只压住底体（顶体仍醒、末窗 `|ω|` 0.020） | 未测 | ⚠️ 不够 |
| `stab=2` | **仍醒**（清零 2998/3000） | 最大 67 次 ⇒ **1.340/s** | ✗ 单用**变差** |
| `K=8`（唤醒门） | 只有 2 体、接触数不够 K ⇒ 与 K=0 逐位相同 | 最大 2 次 ⇒ **0.040/s**、角速 hot **0** | ⚠️ 只压传播不除根 |
| `maxcorr=0` | 入睡但下沉 30 cm | — | ✗ 只是归因 |
| m1_pile 配方 `16/4/shock2/stab2/K8/hold4` | **入睡**（bias 记账 → 0） | 未测 | ✅（配方档） |

⇒ **`substeps=4` 是全场景里唯一「过 + 长时程也过」的旋钮，但它治不了最小对**（偏航对在 4 子步
下仍留 `|ω| ≈ 0.08`）；取舍留给 `ROUTE.md` ①（`wake_gate_k` / C6 视野）那条**使用者裁决**，
本表只供读数。**旧口径的代价**：把根因读成「接触闪烁极限环」会去修唤醒迟滞/分档睡眠
（两条都不是这条链上的东西）。
