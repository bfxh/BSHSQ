## P8 — `sat` 的面轴断言与自身契约矛盾 ✅ **已清（2026-09-22）**

`crates/vxl-phys-narrow/src/lib.rs` 的 `sat()` 里原文（T3 盒对快路径提交 `9883dbc` 引入）：
```rust
debug_assert!(box_axes.is_some() || (na == 6 && nb == 6));
```
**为什么是错的**（分派侧查证）：盒对走 T3 专用路径、轴由 `(rot, half)` **直生**、**不填多面体**；
圆柱/圆锥参与的对走通用分支、进 `sat` 前**已 `poly_*.fill`**（世界多面体缓存命中则用同 (体,多面体)
的上一次填充）。圆柱是 **18 面**（`CYLINDER_SEGMENTS = 16` + 两端面）⇒ "非盒对且 6 面"这个条件
**永远不成立**，而紧随其后的 `match box_axes { None => (na, nb) }` 明确要读 `na/nb` ⇒ 断言把自己的
契约写反了。触发：`cargo test -p vxl-phys --test rolling_probe`（圆柱在盒地板上滚动）。

**处置**（改断言、不删）：换成**真契约**并通过实测验证——
```rust
debug_assert!(box_axes.is_some() || (na > 0 && nb > 0), "通用路径的多面体必须已填：na={na}, nb={nb}");
```
它抓的是**真 bug**（"进了通用路径却没填多面体" ⇒ 轴表为空 ⇒ 静默出垃圾接触），而不是"圆柱不该来这儿"。

**验证**：`cargo test --workspace`（**debug**，先前唯一红）⇒ **52 个测试目标全绿、零 panic**
（新断言在整套场景里无误报 ⇒ 契约被实测钉住）；`cargo test --workspace --release` 全绿；
`m0_gates` 三读数**逐位不变**（`0x6536fa72…` / `0x417be20a…`）——`debug_assert` 在 release 被编译掉
⇒ **零性能影响**（T3 窄相峰值不受影响，无需重跑计时门）。

**教训**：`debug_assert` 被 release 编译掉 ⇒ **CI 跑 release 时它会静默**（本次 CI 一直全绿、
只有 `cargo test --workspace` 的 debug 档才暴露）⇒ 写"只有 debug 才看的门"时要有人跑 debug。

## P11 — 喷溅域"质量"两读未统一 ✅ **已定案（2026-10-08 同日）**：质量 = **介质密度场的积分质量**

**定案口径**：`Splat::mass(ρ_medium) = ρ_medium·opacity·(2π)^{3/2}·σx σy σz` ——
它就等于 `∫ ρ_medium·σ(p) dV`（`σ = opacity·exp(−½α)` 的解析积分）。`opacity` 回到它本来的
身份：**密度场的权重**（渲染/隐式场），不是质量；`flow.rs` 的动量分摊与 `StateBridge` 导出的
质量**都调这一个函数**（单一来源）。`medium_density ≤ 0`（没声明介质质量）⇒ 桥侧按
**未登记**处理（`mass` 留空、`momentum()` 返回 `None`），不是"质量 = 0"。

**验收判据（缺一不可，全部已落地）**：① `Σ mᵢvᵢ`（桥的口径）与 `deposit` 的分摊账在同一场里
自洽（`splat_state_bridge.rs`：`p == absorbed`，相对 1e-5）；② **数值积分对拍**闭式质量
（`splat_mass.rs`：144³ 中点法 vs 解析，相对 < 5e-3）；③ `mass` 是**派生量** ⇒ 篡改过的质量
快照被拒绝（不许把派生量当独立状态写进去）；④ 默认档逐位不变（`two_way = false` 的既有判据
与金样门）。

### 原登记（保留为设计记录）

**现状**：同一颗高斯核在两处被当"质量"用，口径不同——

1. 模块头与 `StateBridge`（`src/splat_access.rs`）按 **`opacity`**：`Splat::opacity` 的注释就是
   "不透明度 / 权重（密度和中的系数；物理上 = 该核的质量）"；
2. `flow.rs` 的**动量分摊**按 **`kernel_mass = ρ·(4/3)π·σx·σy·σz`**（1σ 椭球体积 × 介质密度），
   它的注释写着"只是动量分摊的口径，不动核的几何"。

⇒ 于是 `deposit` 注入的动量 `J` 满足 `Σ kernel_mass·Δv = J`，而 `BridgeState.momentum()` 算的是
`Σ opacity·v` —— 两者**不是同一个账**（实测：同一场里 `opacity` 与 `kernel_mass` 相差数量级）。

**为什么不在这片修**：改任一侧都会动到已落地的语义（`opacity` 是渲染/密度场的参数，
`kernel_mass` 是动量守恒账），而"统一到哪一个"是**设计拍板**（属 splat ②"物理代理"那片：
splat 当粒子域时，粒子质量与不透明度是两个概念还是一种？）⇒ 本轮选择**不静默改**，
在 `CAPABILITIES.yaml` 的 `PHY-SCOPE-SPLAT` 里如实登记两读。

**候选入口**：② 物理代理落地时，给 `Splat` 增一个显式质量字段（或声明 `opacity` 就是质量、
把 `kernel_mass` 改成读它），并让 `deposit` 与 `BridgeState.mass` 走**同一口径**。

**验收判据（缺一不可）**：① `Σ mᵢvᵢ`（桥的口径）与 `deposit` 的分摊账在**同一场**里逐位自洽；
② 默认档（`two_way = false`）逐位不变（金样门）；③ 渲染桥导出的 `opacity` 语义不变
（`export_splats` 的 5 元组逐值不变）。

## P12 — 喷溅"内聚/表面张力" ✅ **已落地（真路①：显式吸引偏置）**（2026-10-08 同日）

**做法**：`SelfPressure::cohesion`（Pa，**默认 0**）—— 在对循环里把 EOS 压力**减去**这个偏置再代入
同一个对称式：`(p_k − cohesion)/ρ_k² + (p_j − cohesion)/ρ_j²`。`cohesion = 0` 走另一条分支 ⇒
**逐位不变**；两条腿共用同一套 `dv[k] += a·m_j; dv[j] -= a·m_k` ⇒ 动量守恒照旧是构造出来的。

**为什么这样最好**：把"平衡"变成**解析可算**的量 —— **平衡密度由 `p(ρ) = cohesion` 定义**
（两核时 `ρ/ρ0 = 1 + exp(−d²/2σ²)` ⇒ 平衡间距 `d_eq` 闭式）。判据就不再是"看着像"，而是对拍：

| 判据 | 实测 |
|---|---|
| 解析 `d_eq`（cohesion = 2300 Pa ⇒ ρ_eq/ρ0 = 1.5） | 0.2354 |
| `0.9·d_eq` 处净力 | **斥力**（相对速度 +1.887e-2） |
| `1.1·d_eq` 处净力 | **吸引**（−1.535e-2） |
| 自由演化（零重力、每步阻尼 0.95、900 步）末态间距 | **0.2354**（目标 0.2353） |
| 末态速度 | 2.5e-7 |
| 不等质量动量账 `Δp` | 相对 < 1e-6 |

**真路②（保留为备选）**：改 `ρ0` 口径（取"多核密集态"平均密度）⇒ 才存在真正的稀疏带；代价是
P11 的 4 条判据都要重标。**两条路都不许**"去掉 `p ≥ 0` 钳制了事"（见下）。

### 原登记（保留为设计记录）

**结论**：P11 定案的质量口径（`m = ρ·opacity·V`、归一化核 `w(0) = 1/V`）让**孤立核的自密度恒等于
`ρ_medium·opacity`**；任何邻居都只会把 `ρ` **抬高** ⇒ Tait 压力 `p = B((ρ/ρ0)^7 − 1)` 在
`ρ0 = medium_density·opacity` 的档里**恒 ≥ 0**（钳制与不钳制都一样）⇒ **没有"稀疏带吸引"**，
压力永远是纯斥力。

**证据**（`crates/vxl-phys-splat/tests/splat_pressure.rs` 的扫距判据）：`d/σ ∈ (0.1, 3.9)` 全带上，
两核相对速度变化的最负值是 **0.000e0**（推开或无力，绝不吸引）。超过 `4σ` 则被截断 ⇒ W = 0。

**要做内聚/表面张力，只有两条路**（都得先定判据与标定，别顺手加负压）：
1. **显式吸引项**（Akinci 式内聚力/表面能）：另立一个吸引核（或对 `w` 取另一条曲线）与系数
   `γ`、作用带（约 1–2σ）；必须给**上界**（不许把"负压 + 大 W"叠成爆炸性吸力 —— 液体侧留档过
   `Δv ~ 10² m/s` 的同款事故）。判据：稀疏两核**相互靠近**、总动量守恒、`N` 步内 |v| 有界无 NaN、
   默认关时逐位不变。
2. **改口径**：让 `rest_density > medium_density·opacity`（即 `ρ0` 取"多核密集态"的平均密度）⇒
   才存在真正的稀疏带；代价是要重新标定质量口径与既有判据（P11 的 4 条判据都会动）。

**登记动机**：这一条是"口径定干净"的副作用，不是缺陷 —— 记下来是为了拦住"顺手把 `p ≥ 0` 钳制
去掉就能做内聚"的弯路（那只是在没有稀疏带的情况下制造负压 ⇒ 只会得到噪声级的假吸引或爆炸）。

## P13 — 快速销毁的**下一刀**：每种子一次"全区域扫描" ✅ **已落地（2026-10-09 同日）**

**做法**：给每个种子算一个**保守 AABB**（`voxel_voronoi.rs::seed_box`）——把外区域盒用与其余种子的
**二分面半空间**（`|p−sᵢ|² ≤ |p−sⱼ|²` ⇔ `2p·(sⱼ−sᵢ) ≤ |sⱼ|²−|sᵢ|²`）逐次裁剪，每轴保守收缩；
最后**向外扩一格**并夹回外区域（保住"盒 ⊇ 胞"，且 `extract_where` 用 `floor` 取格时不漏边界格）。
提取扫描从"全区域"降到"该种子的邻域"。

**实测（24³ 格、release；只报数不判）**：

| 种子数 | 归属图 + AABB | 朴素 | 加速 |
|---|---|---|---|
| 16 | 0.58 ms | 1.06 ms | 1.8× |
| 32 | 0.98 ms | 2.60 ms | 2.7× |
| 64 | 1.66 ms | 5.79 ms | 3.5× |
| 128 | 2.70 ms | 23.54 ms | **8.7×**（上一刀是 4.7×） |

**判据（两层都过）**：① 与"朴素陪测"**逐位一致**（`tests/voronoi_parity.rs`，三个场景）；
② **`m3_collapse` 金样哈希不变**（覆盖整条破坏管线）。

**踩到的坑（写下来省下一轮）**：保守裁剪的**方向**极易写反 —— 求 `pᵢ` 的上/下界时，其余轴都要取
**最小贡献**（`aᵢ > 0` 时 `pᵢ ≤ (b − min T)/aᵢ` 是最大上界；`aᵢ < 0` 时 `pᵢ ≥ (b − min T)/aᵢ` 是最
宽松的下界）。我第一版取了"最大贡献"，盒被缩得比胞还小 ⇒ 提取**全空**；正是那条"朴素陪测"当场
抓住（否则金样只会报"碎块数变了"，看不出根因）。

### 原登记（保留为设计记录）

**现状**：`voxel_voronoi.rs` 的一遍归属图把 `fracture_voronoi` 的复杂度从 `O(格数×种子数²)`
降到 `O(格数×种子数)`（实测 16/32/64/128 种子 = 1.3/1.9/2.6/**4.7×**；新实现线性、朴素二次）。
**剩余项**：每个种子仍要扫一遍**整个区域**做贪心合并（谓词只是一次查表 ⇒ 便宜但仍是 `× 种子数`）。

**候选做法（论文里的标准招）**：给每个种子算一个**保守 AABB** —— 把外区域盒用与其余种子的
**二分面半空间**逐次裁剪（`|p−si|² ≤ |p−sj|²` 是线性不等式 ⇒ 逐轴保守收缩，结果盒只需**包含**
该种子的 Voronoi 胞），然后把 `extract_where` 的区域换成这个盒。
⚠️ 两个坑：① 裁剪必须**保守**（宁可盒大，不可漏格），边界要**向外取整到格**；② 盒一变，
`extract_where` 的扫描起点就变，必须证明"被裁掉的格里没有该种子的格"⇒ 盒列表仍然逐位一致。

**判据（缺一不可）**：① 与朴素陪测**逐位一致**（现有 `voronoi_parity.rs` 直接复用）；
② **`m3_collapse` 金样哈希不变**；③ 成本扫描里 128 种子档的加速比**再降一档**（当前 4.7× 是基线）。

## P15 — 真实性基准 R5：高质量比静默互穿 ✅ **已修（2026-10-09 同日，零换代）**

**结论**：根因是**迭代预算被写成全局常数**，而收敛难度是**每岛属性**。默认档 2×3 在质量比
≥15 时传不动"重压轻"的支撑载荷 ⇒ 轻盒被按穿地面、与重盒互穿。修法 = `shock_budget.rs::
island_shock_budget`：shock 附加扫掠按岛给，仅当"岛内质量比 > 8 **且** 主迭代残差 ≥
`early_exit_eps`"时追加 `ceil(2·log2(比/8))` 次（上限 16），显式 `shock_iterations` 仍是下界。
**收敛门**让"质量比大但本就收敛"的场景（如 `mesh_vs_mesh` 的 20:1 双面片）逐位同旧。
**实测**：R5 `first_fail_ratio` **20 → 1000**（r ≤ 100 全部通过）；`determinism` /
`m0_gates` / `m1_islands` / `scale` / 金样 8 项（含 `m3_collapse` 哈希）**全部逐位不变**
⇒ **零换代**（本仓第三次"改引擎而无需换代"）。R5 判据同步收紧 20 → 100。机理与扫描见
`KNOWLEDGE.md` §O / `EXPERIMENTS.md` 同日段。

### 原登记（保留为设计记录）

**现状**：两盒叠放（上盒质量 = r × 下盒，默认档 `substeps=2 / iter=3`，600 tick），失败判据
`nan | pos_err>0.08 m | depth>4·skin(0.08 m)`：

| r | max_depth | final_pos_err | fail |
|---|---|---|---|
| 1 / 2 / 5 / 10 | 0.0032 / 0.0079 / 0.0152 / 0.0333 | 0.0035 / 0.0090 / 0.0049 / 0.0143 | 否 |
| **20** | 0.1120 | 0.0457 | **是**（深度越界） |
| **30 / 50 / 70 / 100** | 0.200 / 0.198 / 0.229 / 0.454 | 1.0002 / 1.0009 / 1.0026 / 1.0002 | **是** |
| 1000 / 1e4 / 1e5 / 1e6 | 0.973 / 0.993 / 0.992 / 1.072 | ≈1.000 | **是** |

**要害**：r ≥ 30 时上下盒**同位**（pos_err 恰约 1.000 m = 一整个盒高）且 **nan = 0** ⇒ 不是发散，
是**静默互穿**：下盒被重盒按穿地面，末态看起来"叠住了"，其实已经嵌合。`first_fail_ratio = 20`。

**为什么值得单列**：这不是"数值不好看"，而是**错误沉默**——没有 NaN、没有报错，调用方拿到的
是一个物理上不可能的稳态。质量比 20 在破坏/碎片/角色叠罗汉里都很常见。

## P23 — FLIP 的 **APIC 仿射传输**：派生 `C` **买到旋转红利**，近静场代价未消 ⚠️ **开（默认关 = A/B 档）**

**读数**（`crates/vxl-phys-fluid/tests/flip_rotation_probe.rs`：
`flip_apic_derived_c_buys_rotation` + `#[ignore]` 诊断 `diag_apic_rotation`；
静水槽 A/B 一栏在 `flip_incompressibility_probe.rs::diag_apic_hydrostatic`）。

台架 = 零重力**旋转团**（立方水团绕竖直轴刚体旋转、`set_boundaries(&[])`、默认
`dynamic_viscosity = 0` ⇒ **无边界、无体外力** ⇒ 末态 `L_y` **只可能被 P2G/G2P 那一趟三线性传输
耗散**）；`l_keep` = 末态/起步角动量、`rot_err` = 去平移后偏离刚体旋转的相对 RMS：

| 档位 | `l_keep` | `rot_err` | `ke` | `vmax` |
|---|---|---|---|---|
| PIC（`θ = 0`） | 0.1453 | 0.8644 | 4.77e0 | 0.127 |
| **PIC + APIC** | **0.9814** | **0.4291** | 1.61e2 | 0.763 |
| FLIP（`θ = 0.95`） | 0.8655 | 0.4519 | 1.31e2 | 0.894 |
| **FLIP + APIC** | **1.0729** | 0.6664 | 2.41e2 | 1.864 |

⇒ `θ = 0` 档开 APIC 把 `l_keep` 从 **0.145 抬到 0.981**（≈ 无耗散）、`rot_err` **腰斩**
⇒ **派生 `C` 真的买到了 SPEC §4.8 要它治的那条病**。`ke` 那列看着大，但它是**自洽**的
（`ke ≈ L²/(2I)`；把 `C` 写死成解析真值 ω× 的对照读数 `l_keep` 1.081 / `rot_err` 0.138）
⇒ 是"少耗散"，不是"能量爆走"。静水槽（60 tick × 4 子步、80 次 CG、`θ = 0.95`）
`ke` 17.24 → **20.35（+18%）**、`sink` 3.21e-2 → **3.50e-2（+9%）**；代价集中在**近壁**：全体过密
`over` 3.603 → **4.138（+15%）**而**体内部** `over_in` 0.856 → **0.332（−61%）**
⇒ 既有判据全不破、**体内部**重叠明显变好（近壁变差），但近静场要付一笔温和的动能账。

**做法（与上一版的关键差别）**：`C` 不再从**网格**速度场重建，而是每子步由
`flip/affine.rs::estimate_from_field`（`flip.rs` 的 `p2g` 开头）**从粒子场现算**：
邻居 `|p_j − p_i| ≤ h` 上做加权最小二乘 `C = M·D⁻¹`（`M = Σ w·(v_j − v_i)⊗(p_j − p_i)`、
`D = Σ w·d⊗d`，`w = 1 − r/h`；邻居用 `src/grid.rs` 的确定性 27 邻域网格 ⇒ 求和序是位置的确定函数）。
`C` **不落任何跨 tick 缓冲** ⇒ 不进粒子状态，逐位复现 / 保存恢复 / 状态继承三份契约**零换代**。

两处驯服 + 一条退化兜底（不驯服时静水槽 `ke` 17.2 → **80.1**、过密 `over` 3.6 → **18.5**，不可用）：

1. **岭** `λ·(tr D / 3)`（`λ = 1e-2`）：表面粒子邻域是单侧的 ⇒ `D` 在缺失方向欠定，不压住就会把那侧
   **偏置拟合成假梯度**（"粒子贴壁 ⇒ 邻域只在一侧 ⇒ 拟出一个不存在的剪切"）；
2. **拟合质量收缩** `C ← (⟨C, M⟩ / T)·C`：`T = Σ w·|v_j − v_i|²` 是局部速度总散布、`⟨C, M⟩` 是被线性
   模型解释掉的那部分（最小二乘性质保证 `⟨C,M⟩ ≤ T` ⇒ 收缩因子 `s ∈ [0, 1]`）⇒ 近静场里"信号"几乎
   全是噪声时 `s → 0`、`C` 自动哑火（`T = 0` 时直接 `C = 0`）。
3. `D` 真退化（`det D ≤ (tr D / 3)³·1e-6`，**相对**判据：`D` 是世界单位、绝对值随 `h` 缩放）或非有限
   ⇒ 该粒子这一子步退回 FLIP/PIC 传输。

**历史（上一版的负结果，保留作证据）**：`C` 从**网格**重建、每 tick 清零时，零重力旋转团 `θ = 0` 档
角动量保持率只有 **0.145 → 0.155**（≈ 无差别）。机理：`C` 每 tick 清零 ⇒ 首子步就是纯 PIC/FLIP 传输；
而 PIC 的 `v ← v_网格` 重置把粒子场在**同一格的 8 个节点**上拉平 —— 粒子越靠近格子中心越彻底，
此时一阶矩 `Σ w·v⊗d` 因 `Σ w·d = 0` 且 `v` 逐节点相同而**抵消** ⇒ 从该网格场估出的 `C` 是"被磨过
一次"的梯度 ⇒ **自洽退化回 PIC**。**那条推导没错，错的是结论的范围**：它只说明"从网格重建 `C` 不行"，
不等于"APIC 不行" —— 从**粒子场**现算就绕开了那道自洽环（粒子场的跨格差分别没被磨过），
而且因此**不需要**把 `C` 塞进粒子状态（原先估计的"契约换代"这一刀是多余的）。

**判据器械**：`flip_apic_derived_c_buys_rotation` 把**正结果**钉成六条 —— ① 台架判别力
（FLIP > 4× PIC）；② `θ = 0` 档 APIC > 4× PIC **且 < 1.05**（不过冲：驯服前 1.033、解析真值 1.081）；
③ `rot_err` < 0.6× PIC；④ FLIP 档开 APIC 不劣 3%；⑤ **默认关**（`FluidConfig::default().flip_apic`
必须 `false`）；⑥ A/B 档逐位复现（含 `digest`）。

**候选出口**（择一，都要先量）：

1. **把目标场景的代价压到 0 再默认开**：静水槽 +18% `ke` / +15% `sink` 是当前的账。要么承认它是
   "少耗散"的必然代价并改判据口径，要么找到产生它的具体通道（见 2）；
2. **MAC 面一致的评估点**：本实现把三个分量都按**角点**偏移评估（`C·(x_角点 − x_p)`），而 `u`/`v`/`w`
   面各自相对角点有**半格错位** ⇒ 在 FLIP 档注入 `O(½·grid_step·|C|)` 的伪仿射速度。**怀疑静水槽那 +18%
   `ke` 有它一份**（旋转团那栏 `l_keep` 已 ≈ 1，掩盖了它）⇒ 先把评估点搬到"各分量自己的面"（= 面
   中心的三线性插值权重）再重测静水槽该栏，这是最便宜、且可能顺手把 `ke` 拉回来的一个；
3. **更细的岭/收缩口径**：`λ` 与收缩指数现在是两处手调常数（`1e-2` / 线性）。可在静水槽 + 旋转团
   两栏上做一次小扫描，看能否把 +18% 压到 +5% 以内而 `l_keep` 不掉；
4. ~~`C` 进粒子状态（契约换代）~~ —— 已被本轮**否证为不必要**：从粒子场现算就不需要 `C` 活过子步。

**结论口径**：`flip_apic` = **A/B 实验档**（默认 `false`，与 `dynamic_viscosity = 0` 同一先例）。
开档的收益是旋转/密度重叠（`over_in` −61%），代价是近静场的动能（+18% `ke`）；两者都已进代码内
文档（`src/config.rs` 的字段 doc、`src/flip.rs` 模块头 `## APIC` 节）与判据，默认值不动。

## 2026-10-17 — `Distance` 关节在 `rest ≠ 初始距离` 时把间距压到 0（**已修**，根因见本节末）

- **现象**：静态锚点 + 动态球、`JointKind::Distance`、`rest = 0.5`、初始间距 `0.8` ⇒ 间距在
  **4 个 tick 内**掉到 0 并**停住**（不回弹到 0.5）。实测轨迹 `0.932 → 0.081 → 0.0129 → 0`，
  关节字段确认 `rest = 0.5` 已正确写入 ⇒ 不是"参数没设"。
- **影响**：`rest` 形同虚设 —— 想用距离关节做"定长绳"并把两端**拉到**目标长度时行为不可用。
- **绕开方式**：让 `rest` **等于初始间距**。solver 自己的 `distance_holds_rest_length` 就是
  这么写的（注释也点明"静止长度取初始真实距离"），所以这条缺陷一直没暴露。
  M6 浮体系泊金样（`m6_float_mooring`）按此口径构造。
- **当时的处置**（⚠️ 事后证明判断有误，见本节末「已修」）：当时认为修它要动 `linear_rows` 的 `Distance` 分支（位置偏置的方向与幅度），属求解器
  核心；需要先有"改变长度"的判据与对照场景。本轮范围是加"可断裂"功能，不顺手改核心。
- **可复现**：`tests/joint_break.rs` 头注记录了这个坑与第一版的失败轨迹。
> ✅ **已修（2026-10-17）**：根因是 `linear_rows` 的 `Distance` 分支**冲量符号写反** —— `lambda` 算成 `-(v·n + bias)/k`，第一次迭代后 `v·n` 与偏置**同号** ⇒ 迭代发散（实测 `v·n` 序列 `0 → −7.2 → −21.6 → −50.4 → … → −914`，间距一步 0.8→0.0129、第二 tick 到 0 永停）。正解是 `(bias − v·n)/k`；改后间距单调收敛（`0.8 → 0.692 → 0.623 → … → 0.5012`）。回归判据 `tests/joint_break.rs::distance_rest_differs_from_initial_distance_converges`。全仓测试 0 失败；`m6_float_mooring` 只有「被拉住」档的 `v_y` 从 `+1.425e-6` 变 `−1.425e-6`（同量级、只翻符号，`y` 位模式不变），基线已随之更新。

### 探针复现（2026-10-17，`rest = 0.5` / 初始间距 `0.8` / 静态锚点 + 动态球）

逐 tick 的间距：`0.932001 → 0.079616 → 0.012897 → 0 → 0 → …`（永不回到 0.5）。

当时的两个猜测（**事后证明都不是根因** —— 真因是冲量符号写反，见本节末）：
- **一步就冲过头**：`bias = -(len − rest)·bias_inv_dt`（`bias_inv_dt = baumgarte·inv_dt`），
  `len − rest = 0.432`，若 `baumgarte = 0.2`、`dt = 1/60` ⇒ 一步的目标位移约 `0.086 m`，
  实测却一步掉到 `0.0796` —— 看起来是**多迭代叠加**（同一子步内 `solve_joint` 被调多次，
  每次都用"当前 `err`"重算偏置）把目标吃穿了。
- **退化后不再修正**：`len <= 1e-6` 时 `linear_rows` 直接 `return 0.0` —— 方向 `n` 未定义，
  于是关节"松手"，之后永远停在 0。若要修，正确做法是**持久化方向**（Box2D 的 `u` 那样），
  而不是每次从 `err` 现算；但那需要给关节加状态，而 `Joint` 是 `Copy` 且 `max_type_members`
  是只准降的棘轮 ⇒ 得走 `Breakage` 那种并行数组的路子。
- 试过把 `lambda` 的符号翻过来，行为**完全不变** ⇒ 符号不是根因（`apply_pair` 的约定
  "b 侧 +imp / a 侧 −imp" 与这里的符号是自洽的）。

止损原因：根因在"偏置在迭代内反复累积"这一层，要动的是求解器的迭代结构，而不是一行符号；
本轮范围是验证缺陷是否真实存在（**确认存在**），不顺手改核心。
