# 统一求解器设计评审（`PHY-SCOPE-UNIFIED-SOLVER`）

> **状态：评审中，未决议、未动代码。**
> 这份文档是 `docs/CAPABILITIES.yaml` 里 `PHY-SCOPE-UNIFIED-SOLVER` 那条立项门要求的第一步：
> 补齐 `shared_state_design` / `constraint_jacobian_residual` / `mass_inertia_treatment` /
> `solve_order_and_convergence_criteria` / `baseline_scenario` 五项证据，**再**决定是否值得迁移。
>
> 按 §15.4：双向力交换、同一个函数循环、共享线程**都不能**证明"统一求解器"。
> 在决议前，禁止"共求解器已支持"类宣称，也不得默认开启。
> 现役门禁：`crates/vxl-phys/tests/xpbd_solver_gate.rs`（`ElementKind::Xpbd` 零消费者即绿）。

## 0. 现状是什么（先把事实摆清）

`ElementKind` 枚举有五个变体（`Contact` / `Joint` / `Xpbd` / `Medium` / `Ccd`，
`crates/vxl-phys-core/src/interop.rs:98`），但**五个全都没有消费者** ——
唯一的引用是 `interop.rs:329` 的 trait 方法声明 `fn kind(&self) -> ElementKind`，仓内零实现。
所以"统一求解器"目前是**一个枚举 stub**，连骨架都不存在。

对照 `BridgeKind`（同文件 `:83`）—— 它有三个真实消费方：
`vxl-phys-splat/src/splat_access.rs:23`、`vxl-phys-fluid/src/fluid_access/state.rs:19`、
`vxl-phys-soft/src/cloth_access.rs:30`。这两个枚举的成熟度差得很远。

### 实际在跑的编排（`crates/vxl-phys/src/world_step.rs`）

一个 tick 分成两层：

**第一层：子步循环**（`step()` `:20`，`substeps` 次调用 `substep(dt)` `:270`）

```
0) NaN 隔离
1) 力场 → 介质耦合(medium_pass) → aero_pass → splat_dynamics::pass → fluid_reaction_pass
2) 速度积分
3) 宽相
4) 窄相
5) 求解（接触 + 关节）→ 岛级休眠 → film::pass
6) 位置积分
7) 选择性 CCD
```

**第二层：域通道**（`domain_pass()` `world_soft.rs:94`，在子步循环**之外**）

```
fluid_pass() → rope_pass() → cloth_pass()
```

**这就是"反作用耦合 = 下一 tick 生效"的物理来源，也是本评审要回答的核心问题**：
软体/流体域在**子步循环之外**推进，它们对刚体的作用通过 `dv` / `dx` 交付，
而 `dv` 的注释写得很明白（`crates/vxl-phys-soft/src/cloth_coupling.rs:48`）：

> 体的速度增量（门面 `bodies.linvel[j] += dv[j]`）：引擎在体解算**之后**施加
> ⇒ **下一 tick 生效**。

## 1. `shared_state_design`：共享状态与所有权

### 现状：每个域有自己的状态宿主

| 域 | 状态宿主 | 形态 |
|---|---|---|
| 刚体 | `BodySet`（`position` / `linvel` / `angvel` / `inv_mass` 等平行数组） | 数组-of-结构体拆成结构体-of-数组 |
| 关节 | `JointSet`（`joints` + `breakage` / `impulse` 等**并行数组**） | 同上 |
| 布料 | `ClothSheet`（粒子、约束表、`BodyCoupling`） | 每个布片一个实例 |
| 绳索 | `Rope`（同量级） | 每个绳索一个实例 |
| 流体 | `FluidSystem`（PBF 粒子 / FLIP 网格） | 每个系统一个实例 |
| 喷溅 | `SplatField` + `SplatDynamics` | 全局一张场 |

刚体与关节已是"结构体-of-数组"，这是**利于统一**的一面 —— 约束只要索引对，就能跨域取到质量与速度。
难点在布料/绳索/流体：它们是**独立实例**，粒子索引空间与 `BodySet` 不共享。

### 候选设计：全局元素表 + 域内偏移

统一求解器若要做，最小可行的共享状态是：

```
struct ConstraintGraph {
    // 每个约束行：两端元素 + 该行的雅可比 + 累积冲量 + 边界（μ / λ_min / λ_max）
    rows: Vec<Row>,
}
struct Row {
    kind: ElementKind,     // 这个枚举终于有用了
    e0: ElemRef,           // 元素引用（域 + 域内索引）
    e1: Option<ElemRef>,   // 单边约束为 None（如接触对静态体）
    jac: JacobianBlock,    // 见第 2 节
    accum: f32,            // 累积冲量（warm start 的载体）
}
```

**所有权原则（建议写进决议）**：约束图**不拥有**任何元素状态，只持有 `ElemRef` 引用。
所有位置/速度仍归各域自己管，求解器通过一次 `gather` / `scatter` 读写（与现役
`solve_phase` 的 `gather → solve → scatter` 同构，`solver_impl.rs:70` 的编排注）。

**这一条决定了迁移成本**：现役刚体路径已经有 `gather/scatter` 骨架，布料/绳索/流体**没有**。
要给它们接上，等于把三次域内循环改造成"可在任意迭代次数下被中断和续跑"。

## 2. `constraint_jacobian_residual`：雅可比与残量口径

### 现役各域的约束形式不一样，这是最硬的分歧

| 域 | 约束形式 | 施加方式 | 残量口径 |
|---|---|---|---|
| 刚体接触 | `Manifold`（含 1–4 个接触点）+ 库仑锥 | 顺序 Gauss-Seidel，`solve_groups`（`solver_impl.rs:318`） | 法向相对速度 / 切向漂移 |
| 关节 | 精确行（铰链 2×3 行、滑块、距离） | `joints/solve.rs`，独立迭代预算 `joint_iterations` | 位置误差 + Baumgarte 偏置 |
| 布料 | XPBD 距离/弯曲/体积/自碰撞 | **位置投影**（`λ = -C / (Σw·|∇C|² + α̃)`） | `C`（位置残量，米） |
| 绳索 | 同布料 + 刚体两体约束 | 位置投影 + `BodyHit` 顺序处理 | 同上 + 穿透深度 |
| 流体 | PBF 密度约束 | 位置投影（密度迭代） | 密度约束残量 `C_i = ρ_i/ρ_0 - 1` |
| 流体 | FLIP | 网格投影 + 粒子回投 | **无残量概念**（算子分裂） |

**三种残量口径互不可比**：刚体是速度残量（m/s），XPBD/PBF 是位置约束残量（米或无量纲），
FLIP 压根没有残量。

⇒ 「统一收敛判据」若写成"所有约束的残量同时低于阈值"，在 FLIP 上无法定义，在
XPBD（位置）与刚体（速度）之间也无法直接比较。**这是本评审最重要的发现**。

### 建议的雅可比块

若要统一，约束行的雅可比必须能表达三种情况：

```
struct JacobianBlock {
    // 线性部分：对 e0 / e1 的平移分量（Vec3）
    lin: [(Vec3, Vec3); 2],
    // 角部分：对 e0 / e1 的转动分量（Vec3）；XPBD 粒子为 0
    ang: [(Vec3, Vec3); 2],
    // 有效质量（预先求逆）；0 = 单边/静态
    k: f32,
    // Baumgarte / 柔度：刚体用 β·inv_dt，XPBD 用 α̃ = α/h²
    bias: f32,
}
```

**α̃ 与 Baumgarte 的统一是真正的难点**：XPBD 的 `α̃ = α/h²` 随子步长变化（子步越多，
约束越硬），而刚体的 `β` 是比例系数。两者在数学上可以统一成"约束柔度"，
但**统一后所有现役参数都要重新标定** —— 这正是金样会被全量改写的机制性原因。

## 3. `mass_inertia_treatment`：质量与惯量

### 现状

| 域 | 质量来源 | 惯量 |
|---|---|---|
| 刚体 | `density × volume`（形状积分），或显式 `mass` | 形状积分得到的 `I`，走 `inv_inertia` |
| 关节 | 不参与（挂在刚体上） | 同上 |
| 布料 | 每个粒子 `mass / n_particle` | **无**（质点） |
| 绳索 | 同上 | 无 |
| 流体 | PBF：粒子质量；FLIP：网格单元密度 | 无 |

**统一的关键约束**：XPBD 的位置投影要求解 `λ = -C / (Σ w_i·|∇C_i|² + α̃)`，
其中 `w_i = 1/m_i`。这与刚体 PGS 的 `k = Σ (1/m + J^T I⁻¹ J)` 是**同一个结构**，
只是刚体多了转动项。所以质量口径**可以**统一为"每个元素暴露一个 `inv_mass`，
刚体额外暴露 `inv_inertia`"。

**但布料/流体的粒子质量与刚体质量不在一个量级上**（布片 0.5 kg 分给几百个粒子 ⇒ 每粒 ~1 g），
统一求解器里如果让刚性接触和布片粒子出现在**同一个 Gauss-Seidel 队列**，
一次接触迭代的冲量对布片粒子的影响会远大于对刚体 —— 收敛速度由最软的元素决定，
这可能让刚体侧反而变慢。**需要实测，不能靠推理。**

## 4. `solve_order_and_convergence_criteria`：顺序与收敛

### 现役的顺序敏感度是有实测证据的

`cloth_coupling.rs:19` 写得很清楚：

> `body.dv` 是**就地推进**的顺序 Gauss-Seidel ⇒ "谁先被处理"会改变结果。
> 实测（rope，§8.4.23）：把粒子循环反向，常规载重下的横向漂移**符号翻转**
> （0.5 kg：`+0.098 → −0.124`）⇒ 那是**顺序偏差**、不是物理。

⇒ 现役代码用 `BodyHit` 按**几何序**（粒子 `x` 升序）排序来**消除顺序依赖**
（`cloth_coupling.rs:22` 的 `ord` 字段）。

**这对统一求解器是个警告**：把更多域塞进同一个迭代循环，**顺序敏感度只会增加**。
现在只有"布片 → 体"一条边，统一后会有"体 → 布片 → 流体 → 体"的环。
有序性必须重新设计（候选：按元素索引的固定全序，与几何无关；代价是失去局部性）。

### 收敛判据的分类

| 域 | 现役判据 | 可直接统一？ |
|---|---|---|
| 刚体接触 | `resid < eps` 早退（`solve_joint` 同款，`solve.rs:86`） | 是（速度残量） |
| 关节 | 同款 `resid` 早退 | 是 |
| 布料/绳索 XPBD | 固定迭代数（每子步 N 次投影） | 部分（位置残量，单位米） |
| PBF | 固定密度迭代数 | 部分 |
| FLIP | 固定分裂步 | **否**（无残量） |

⇒ 建议的收敛口径：**分区收敛** —— 刚性块用速度残量、XPBD 块用位置残量，
**不试图统一成一个标量**。这样既拿到了"同 tick 内双向迭代"的好处，
又不必为 FLIP 编造一个不存在的残量。

## 5. `baseline_scenario`：可判定的基线

若立项，必须先在**不改引擎**的前提下做出这三个场景的**现役读数**，
作为迁移前后的对照（口径沿用本仓金样：冻结 `f32` 位模式或容差判据）：

### B1 · 布片裹住下落刚体（同 tick 收敛的直接受益者）

布片四角固定或下垂，一颗球从上方落下。判据：
- 球在**接触布片的那个 tick** 内的竖直速度变化 —— 现役应表现为"下一 tick 才被拉住"，
  统一后应当在同 tick 内即可观测到。
- 布片中心的下垂量（是否被球压得更深）。
- 能量账：球 + 布片总机械能不得增加（阻尼存在时只允许减少）。

### B2 · 绳索吊重（顺序敏感度的回归探针）

现役 `rope` 已有 `+0.098 / −0.124` 这个顺序偏差读数（§8.4.23）。
统一求解器若引入新的顺序敏感度，这个数会**最先**变化。
判据：横向漂移保持在现役量级，且**不随运行方向翻转**。

### B3 · 流体推浮体（跨域质量口径的压力测试）

`m5_float_box` 已存在（`crates/vxl-phys/examples/m5_float_box.rs`，720 tick）。
它现在的耦合是"流体 → 体"单向（`fluid_reaction_pass`），体对流体无反馈。
若统一，浮体的位移会改变流体压力场 ⇒ 这是**真正的双向耦合**。
判据：浮体的平衡高度（现役 `盒心 y 1.213774323`）与 `v_y → 0` 的收敛速度。

### 拒绝条件（写进决议，防止"跑通了就算数"）

只要出现以下任一，就应当**否决**迁移：
1. B2 的横向漂移量级变化超过 2×；
2. B3 的平衡高度偏离超过 1%；
3. 任一现役金样（`m3` / `m4` / `m5` / `m6` 共 9 项）需要改冻基线；
4. 36000 体的稠密场景主循环变慢超过 15%。

## 6. 规模与收益评估（给决议用）

### 规模

| 组件 | 行数 | 迁移性质 |
|---|---|---|
| `vxl-phys-solver` | 4,222 | 骨架基本可复用，约束行要泛化 |
| `vxl-phys-narrow` | 8,162 | 只产出约束行，签名要改 |
| `vxl-phys-fluid` | 5,112 | **最大难点**：FLIP 是算子分裂，接不进约束图 |
| `vxl-phys-soft` | 3,045 | XPBD 要改成可中断/续跑的迭代 |
| `vxl-phys-broad` | 3,833 | 基本不动 |

合计约 **2.4 万行**核心。workspace 总量 96,394 行。

### 收益

**真收益只有一条**：同一 tick 内的双向迭代。现役"下一 tick 生效"在大多数工况下够用，
但在**强耦合**（布料包裹、橡胶球压软垫）下会表现为"互相推不进去"或"抖动"。

### 风险

1. **所有金样全变**（9 项）—— 这是交付物上的净损失；
2. 性能大概率下降（专用循环 → 约束图遍历 + 分派）；
3. FLIP 无法纳入（只能保持算子分裂）⇒ "统一"从一开始就是**部分统一**；
4. 顺序敏感度增加（第 4 节）。

### 我的建议

**不立项**，除非出现具体的强耦合需求。若确有需求，先做
**针对性的双向耦合迭代**（例如在布片↔刚体那条边上加 2–3 次交替迭代），
范围可控、金样影响面小、可随时回退 —— 而不是重写整个求解架构。
