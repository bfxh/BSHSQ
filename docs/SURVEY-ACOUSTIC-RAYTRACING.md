# 声学射线追踪与"房间外可闻"：调研 + 本仓落地方案（2026-10-11）

> **读者**：要把"真实声音"接进本引擎的人（集成方 / 音频工具链作者 / 未来的实现者）。
> **结论先行**：① 射线追踪音频这条路**成熟且有成熟件可抄**（Steam Audio / Project Acoustics /
> Meta XR Audio 三家都把"几何声学 + 材质 + 衍射 + 可听化"跑成了实时）；② 本仓**不需要**碰物理
> 求解器就能做——声学是纯**只读消费者**（同 `vxl-phys-sense` 的定位）；③ 用户点名的"**听见房间
> 外的声音**"在文献里对应 **acoustic portal / 孔隙传声**，关键是**声学几何 ≠ 碰撞几何**（缝隙、
> 建模面与碰撞体解耦），这条要在设计上先立住，否则会做成"另一种碰撞"；④ 分期见 §5。

## 1. 技术全景（按"我们能不能用"排序）

| 方法 | 一句话 | 本仓可用性 |
|---|---|---|
| **几何声学：镜像源**（image-source） | 把反射等价成虚拟声源，给**精确**的早期反射 | ⭐⭐⭐ 静态场景的首选（确定性、可解析、无采样噪声） |
| **几何声学：声线追踪**（ray tracing） | 从声源撒射线，命中记路径 | ⭐⭐⭐ 用户点的就是它；与宽相同源（BVH 射线查询） |
| **波束追踪**（beam/cone tracing, Funkhouser） | 用锥体替代射线，减少"漏检" | ⭐⭐ 比裸射线稳，但实现更重；可作二期 |
| **路径追踪 / 声学辐射度**（path tracing / acoustic radiosity） | 蒙特卡洛求**后期混响**能量 | ⭐⭐ 需要降噪/去偏；离线烘焙友好 |
| **衍射**：UTD / BTM（边界衍射波）/ Kirchhoff | 绕角、缝隙的**低频泄漏**与"拐角后仍可闻" | ⭐⭐ **"房间外可闻"的核心**；UTD 是工程主流 |
| **波动声学**：FDTD / FEM / BEM / 波导网络 | 解波动方程，低频/干涉正确 | ⭐ 太重、且与实时无关；只做**离线校验**参考 |
| **散射 / 扩散** | 粗糙面按 scattering 系数把射线打散 | ⭐⭐⭐ 让丛林/树叶那类场景可信（用户提的"树叶遮挡"） |
| **材质与频带** | 各频带的吸声/散射/透射系数 | ⭐⭐⭐ 必须做；**放外部表**（见 §6 禁区） |
| **SIR + 可听化** | 汇成空间脉冲响应，与干信号卷积 | ⭐⭐⭐ 输出层；我们输出**离散 tap**（时延/增益/方向/频带）即可 |
| **双耳/HOA 渲染** | HRTF 或高阶环绕声场 | ⭐ 交给宿主音频引擎（Unity/Godot/Wwise/FMOD），我们不做 |
| **ML 代理模型**（神经 RIR、可微声学） | 学一个"场景→RIR"的近似 | ⭐ 与本仓"确定性/可复现"的契约冲突，**不纳入**（可作离线对照） |
| **GPU 声线追踪** | 复用图形管线做声线 | ⭐⭐ 本仓已有 GPU 档与 BVH，二期可选；先把 CPU 参考做对 |

## 3. 本仓现状与差距

**已有（全部只读可用，不需要动物理）**：

- 几何：`TriMesh`（顶点+三角+面法线+AABB+可选 `MeshGrid`）、体素占据（`VoxelVolume`）、
  `HeightField`、以及窄相自持的 `ConvexHull` 点云；宽相 `BvhBroadPhase`（射线/AABB 查询）、
  `MeshGrid`（桶查询）。
- 事件：`World::impacts()`（逐 tick 峰值冲击）+ `bodies.material[i]`（材质槽）+ `manifolds()`。
- 输出侧先例：`vxl-phys-sense`（`SenseExt` 扩展 trait，cue 流 JSONL，三条契约 + `record/replay`
  工具链）——**声学层就该长成它那样**。

**缺**：① 声学专用加速结构（射线查询要"按声学几何"而不是碰撞几何）；② 材质**声学**属性表
（吸声/散射/透射，按频带）；③ **开口/缝隙**拓扑（portal）；④ 介质体积场（密度/温度/湿度）；
⑤ SIR 输出与积分（能量衰减、早期/后期分界）；⑥ 预算与可复现的采样策略。

## 4. 新能力：听见房间外的声音（"孔隙 + 介质"，与碰撞解耦）

**用户口径（2026-10-11）**：*"可以听见房间外的声音，可以按体积密度等等，可以不受碰撞体的影响，
直接利用建模的缝隙然后听见声音——在有限的条件下还原真实声音。"*

三条设计原则（先立住，再写码）：

1. **声学几何 ≠ 碰撞几何**：声学层吃的是**建模面**（三角网/体素占据/显式 portal），**不看**
   `BodySet` 的碰撞形状。理由：碰撞体为了稳定会被加厚、简化、合并（还有不可见的静态叶），
   拿它当声学几何既过挡（挡声）又漏缝（没有开口语义）。⇒ 声学层自己持一份几何，可复用
   `TriMesh`/`VoxelVolume` 的既有结构（含 `MeshGrid` 桶），但**不读**碰撞体的 `Shape`。
2. **缝隙/开口 = 显式拓扑**：`Portal { 多边形或体素空洞, 两侧区域 id, 透射/衍射系数 }`。
   传播时 portal 当"二级声源"（沿开口方向再发射），这是"房间外可闻"的机制本体；没登记 portal
   的墙体仍可按材质的**透射系数**给少量泄漏（真实隔声 ≠ 全挡）。
3. **介质 = 体积参数场**：`ρ`（密度）、声速 `c`、吸收（空气/雾/水汽）按体素或解析场给；
   声线沿途按 `exp(-∫α dl)` 衰减、按 `c` 变化折转（本仓已有 `vxl-phys-field` 的场注册表先例）。
   "按体积密度"就落在这里：同一束声线穿过水/雾/洞口，得到不同的时延与频谱。

**输出**（与 `vxl-phys-sense` 对齐，避免两套消费协议）：`AcousticCue { 声源 id, 到达时延,
频带能量, 入射方向, 路径类型(直达/反射/衍射/穿缝), 路径长度 }` 的 JSONL 流；上层把它卷成 SIR
再与干信号卷积（我们不碰音频格式）。⚠️ 2026-10-12 补充（A6）：另给了**单声道**离线渲染 + 最小 WAV 读写，供试听与对表；双耳/HRTF 与格式转换仍归宿主。

## 5. 判据与分期（每期都带"可判"的三条契约）

**三条契约**（与感官域同款、CI 可判）：

1. **零干扰**：声学层**只读** ⇒ 开/关它，`state_hash` 逐位不变（不借出 `&mut World`）。
2. **确定性**：同场景同输入 ⇒ **逐字相同**的声学 cue 序列（射线按序、种子显式、无 HashMap 迭代序）；
   工具链直接复用 `record / replay`（跨机器比基线）。
3. **预算**：每 tick 声线数/反弹次数/portal 穿越次数都有上界，超了按优先级截断并**上报**
   （同 `FragmentBudget` / 网格格数预算的口径）。

## 6. 复用点与禁区（施工前先读）

- **能复用**：`TriMesh` 的 AABB/`MeshGrid` 桶、`VoxelVolume` 的占据位、`vxl-phys-broad` 的 BVH
  射线查询、`vxl-phys-sense` 的 cue 流 + `record/replay` 工具链与三条契约模板、`vxl-phys-field`
  的场注册表模式。
- **禁区**：① 不往 `World` 加方法（方法数在尺寸债务账上顶格）；② 不往 `Material` 塞声学字段
  （它是棘轮管的类型）——声学属性放**外部表**（与音色表同口径）；③ 不在 `step()` 里做重活
  （声学是**每 N tick 或离线**的活；实时档要显式声明频率）；④ 不引入 f64/外部依赖（仓规）。
- **工具链**：`vxl-phys-cli` 加 `acoustic <场景> [ticks]`（输出 cue 流）+ `record/replay` 复用即可，
  不必另造一套。

## 7. 边界（写清，不是漏）

- **几何声学在低频失效**：波长与几何尺度可比时（房间尺寸的量级、几百 Hz 以下）射线模型不给干涉与
  驻波；本方案**不承诺**低频正确性，只承诺"高频可闻化"的工程可信度。要低频就离线用 FDTD/BEM 校验。
- **衍射是近似**：UTD 型解法绕角能量偏保守；不做精确波动求解。
- **不做双耳渲染**：输出 SIR/方向，HRTF 与卷积交给宿主音频引擎（Wwise/FMOD/Unity/Godot）。
- **确定性优先于"最真"**：禁止 ML 代理与时间抖动，宁可少采几条射线也要可复现。

## 8. 待裁的三处（需要拍板）

1. **portal 的表示**：显式图元（作者标多边形）还是"体素空洞自动识别"（从占据位找连通孔）？
   前者准、后者省事——建议 A2 先做前者 + 后者作兜底。
   （2026-10-11 更新：**衍射棱**那一半的兜底已落 —— `AcousticGeometry::detect_edges` 自动认边界棱
   与凸棱，前提是三角绕序朝外。**portal 那一半的兜底也已落（2026-10-16，A10）** ——
   `portal::VoxelOccupancy::detect_portals` 从占据位找连通孔：按切比雪夫半径 `neck_cells` 腐蚀断颈
   → 6 连通空域分**房间** → 两房标签**相接**处出 `Portal`（`regions` 填两侧房间 id）。口径仍是
   "显式优先、自动兜底"。）
2. **实时档的频率**：每 tick 追声线，还是每 N tick / 事件驱动（冲击触发）？建议**事件驱动 + 固定
   预算**（与 `impacts` 同源）。
3. **交付形态**：只给 cue 流（宿主自己卷积），还是顺带出一个极简 WAV/IR 转储（供音效师对表）？
   ⇒ **已落（2026-10-12，A6）**：cue 流仍是主交付，另给一个**单声道**离线渲染（`audio.rs` +
   `vxl-phys audio`，见 §5 的 A6 行）；WAV 只做最小集（PCM16 写 / PCM16·float32 读），双耳与格式转换仍归宿主。

## 9. GPU 档的施工状态与计划（2026-10-12；M6 于 2026-10-16 补齐）

**已在卡上**（`crates/vxl-phys-gpu/src/acoustic.{rs,wgsl}`，探针在 `tests/acoustic_*_probe.rs`）：

- **M1 直达**：逐 `(声源, 听者)` 对一个工作项；Möller–Trumbore 遮挡 + `dist/speed` 与 `1/dist²`；
- **M2 一次反射**：逐三角镜像源法 + 两段遮挡，逐对取**最强那条**（平局按三角序号 ⇒ 确定），
  增益 `(1-a)/(d₁+d₂)²`；
- **M3 绕射**：逐棱取 **Fermat 点**（定次数 **48** 的二分，与 CPU 的 `FERMAT_ITERS` 同值 ⇒
  同样的定次数、无早退）、**只在阴影里**产出（直达通视就整对跳过）、逐对取**最强那条**
  （平局按棱序号 ⇒ 确定）；棱表、逐棱系数、**逐棱楔角**（每棱 1 个 `vec4` = `Ω|face0.xyz`，
  2026-10-16 加）各一张缓冲。增益按**是否给了频带**走**两条 lane**：
  - `band_hz ≤ 0`（默认、**旧口径**）：`coeff·(1+cosθ)/2/(d₁·d₂)` —— **逐位不变**（既有探针守这条）；
  - `band_hz > 0`（**A9a/A9b 口径**）：`coeff·knife_gain(ν)·fac/(d₁·d₂)`，`ν = 2√(Δ/λ)`、
    `λ = speed/band_hz`（**宿主**算好传进 `Params.lambda`）、`Δ` = 多余路程；`fac` 是 A9b 楔角
    修正因子（`Ω ≤ 0` ⇒ `fac = 1` ⇒ 逐位回到刀口；`Ω = π` ⇒ `fac = 0` ⇒ 整对不产出）。
- **M4 散射**：逐三角取**面中心**当二级声源（Lambertian）—— 要求**同侧**（法向朝声源那侧、两个
  余弦 > 0）且两条腿都不被挡，逐对取**最强那个面**（平局按三角序号 ⇒ 确定），增益
  `s·cos_in·cos_out·A/(d₁²·d₂²)`、时延 `(d₁+d₂)/speed`。
- **M5 介质积分**：水平层表 + **定步数中点采样**（无早退）—— 逐子段取中点查层表，
  累加 `Σ len/c` 与 `Π exp(-α_b·len)`，输出行是 `(用时, 衰减低, 衰减中, 衰减高)`
  （这条**没有 hit 位**）；**折线（折射）由宿主逐段调用后组合**（时延相加、衰减相乘 ——
  两者都可分量 ⇒ 等价，判据钉了这条组合性）。
- **M6 二阶反射**（2026-10-16 加）：逐对面 `(面 A, 面 B)`（`A ≠ B`，同面连着两次 = 原路返回 ⇒ 跳过）
  做**两跳镜像展开** —— 听者先按 `B`、再按 `A` 镜像，两个反射点都各自落在对应三角内、三段腿都不许被
  **链外的面**挡（链上两张面跳过），逐对取**最强那条**（平局按 `(A,B)` 序号取小 ⇒ 确定），增益
  `(1-a_A)(1-a_B)/(总程长²)`、时延 `总程长/speed`，输出 `w` 报**第一跳**的面序号（诊断用）。
  ⚠️ **卡上不做预算截断**（与 M1–M5 同口径：卡只负责"给定场景逐对取最强"，预算/阶数归宿主）⇒
  与 CPU `reflection_order = 2`（A8）**逐对一致的前提**是 CPU 侧 `max_reflections ≥ n_tris`；
  CPU 的 `dropped_budget` 在卡上没有对应信号。每对 `O(n_tris³)` ⇒ 只对离线、小场景有意义。
  宿主入口单开在 `src/acoustic/reflect2.rs`（`acoustic.rs` 已贴 800 行上限 ⇒ 新腿落子模块，见坑 #5）。

七条探针（M1–M5 五条 + A9a/A9b 对拍 `acoustic_wedge_probe.rs` + 二阶反射
`acoustic_reflect2_probe.rs`，后两条都是 2026-10-16 加的）的参照都
**不是被测的那份实现**（M1 用轴对齐屏障的纯算术判据、M2 用**镜像展开**的
`L = |src' − dst|`、M3 用**手算的对称驻点** + **沿棱暴力扫 20001 点**、M4 用**手写的
`0.5·cosθ`** 与"绕离法向 60° 恰好一半"、M5 用**手算的跨层中点分段和** `2/c_下 + 2/c_上`
与 `exp(-0.8 / -1.6 / -3.2)`；第六条用**手推驻点** + `f64`/Simpson 的独立参照；**M6 用两块
平行平面的闭式展开高度表** —— 与 CPU A8 判据同一张表，见坑 #4 为什么不能再调 CPU），所以不是自证。

**卡上的六条腿到此齐了**（M1 直达 / M2 一次反射 / M3 绕射 / M4 散射 / M5 介质积分 / M6 二阶反射）。
2026-10-16：**绕射里的 Fresnel 积分也上了卡** —— M3 的 A9a **真刀刃** + A9b **一般楔角修正**
已在 `acoustic.wgsl` 落地（宿主多传一份逐棱楔角表 + `band_hz`；`band_hz ≤ 0` ⇒ 旧口径逐位不变）。
参照是探针里**另写的一份 `f64` + `C/S` 走 Simpson 数值积分**的实现（见下"坑"第 4 条），与卡上那份
不同语言、不同精度、不同求积 ⇒ **不是自证**：刀刃 `0.0070336973` vs 参照 `0.0070336955`、
楔角 `0.02813479` vs 参照 `0.028134782`（差 ~`3e-7` = f32 舍入）。

**多次反射这一腿的口径已经拍完并落了**（2026-10-16，M6 = 二阶）。它**不是**"把 CPU 的东西原样搬上卡"：
CPU 侧（A8）有 `max_reflections` 的**逐阶段预算截断**，卡上没有这个旋钮 ⇒ 卡选了**定次数 + 全枚举**
（不截断）这条路：确定、可对拍，代价 `O(n_tris³)`。另一条路（卡上做路径追迹）被否掉的理由是
**随机性会破坏确定性**（真要做就得固定种子 + 定次数，且对拍口径会更难写）。于是"卡上 ≡ CPU
`reflection_order = 2`"这句话**带前提**：CPU 侧也得 `max_reflections ≥ n_tris`（不截断才同解），
这条前提写在 `src/acoustic/reflect2.rs` 的头注与 `acoustic.wgsl` 的 `reflect2` 头注里，避免以后
被当成无条件等价。判据（`tests/acoustic_reflect2_probe.rs`，本机 RTX 4060 Ti 实测 delay `0.016958`
/ gain `0.01891650` 与手算**逐位同屏**）用：两块平行平面的**闭式**（一阶两条 + 二阶两条的高度表，
与 CPU A8 判据同源）+ 三条**几何否定**（单面 ⇒ 没有第二张面可碰 / 反射点出界 / 中段被**全吸收挡板**
挡死 —— 挡板增益 0 ⇒ 抢不走"最强"那位，于是"只遮不反"）+ 表长守卫 + 两跑**逐位一致**。

**施工上已踩到的五个坑**（下一轮直接绕开）：

- **一个探针文件只放一条测试**：`cargo test` 默认并行跑测试函数，每条都会自己 `device_for` 建一个
  wgpu 设备 —— 实测两个设备并存会互相卡死（第一次跑烧掉一个核、629 s CPU 才被手动杀掉）。
  要覆盖多段，就写成**一条**测试里的多段顺序执行。
- **`Params` 是 uniform 结构体 ⇒ 必须补到 16 字节的倍数**：M3 加 `n_edges` 时从 16 B 扩到 32 B
  （少一个 pad 就是整块参数错位 —— 报错会从毫不相干的地方冒出来）。
- **`gpu/src/lib.rs` 是 god 门基线文件**（只准减不增）：加一行 `pub mod ...;` 会直接红 ⇒ 得在同一个
  文件里先删掉一行等量的注释/空行（本仓的棘轮口径见 `god.gate.json`）。
- **后端 crate 不许依赖领域 crate**（2026-10-16 撞上）：`dag-gate` 把 workspace members 列表当
  权威拓扑序 —— `vxl-phys-gpu`（17）**不能** dev-depend `vxl-phys-acoustics`（20），想拿 CPU 的
  `utd` 当参照会被门直接挡下，而且这个方向本身就是要守的（**后端不依赖领域**，dev 也不行）。
  解法：参照在探针里**另写一份**（`f64` + `C/S` 用 Simpson 数值积分）—— 既过门，又比"复用同一份
  实现"更独立。别去调 members 顺序来放行依赖，那是在拆门。
- **`src/acoustic.rs` 已经贴 800 行上限**（2026-10-16 撞上）：M6 的宿主入口（结构体 + 入口函数 ≈ 65 行）
  一加就 810 行 ⇒ `god-gate` 直接红。解法：新腿落**子模块** `src/acoustic/reflect2.rs`，父模块里只留
  `mod reflect2;` + `pub use reflect2::{reflected2_on_adapter, Reflect2Out};` 两行（子模块本来就能用父
  模块的私有 `upload`/`run_entry`/`SceneIn`，不需要把它们改成 `pub`）。以后每加一条腿都照这个走
  —— 别去动 `god.gate.json` 的阈值。

**上卡 ≠ 重写**：这些腿在 CPU 侧都有判据（见本文件 §5 与 `tests/` 里的 `a1..a8` 系列），
GPU 档只是把它们搬到卡上并对拍；⚠️ 本仓 CI 口径是 `cargo test --workspace --exclude vxl-phys-gpu`
⇒ **GPU 探针在 CI 主跑里不会执行**，只能本机或 GPU 探针 job 验。
