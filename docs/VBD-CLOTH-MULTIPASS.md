# VBD 布料边：多遍收敛的记账缺口与拆法（立项稿）

> 结论先行：**布料边的多遍不成立，不是参数问题，是记账问题。** 现在 `apply_body_hit` 是一个
> 不可重入的整体：它同时算 λ、做速度钳位、走 make-up、推粒子、回填反作用。块求解的"残余穿透"
> 只能在函数外面用 `λ·(w_p+w_b)` 记，**钳位截掉的那一份与 make-up 补的那一份都不在账上**
> ⇒ 第二遍看到的残余既不是真实残余，也不是零。

## 1. 现状读数（2026-10-30，四角钉住布兜 + 动态盒，600 tick）

| 遍数 | 盒末 y | 应变 |
|---|---|---|
| 现役（排序 + 就地 GS） | +0.0003 | 0.0098 |
| 块 ×1 | +0.0004 | 0.0103 |
| 块 ×4 | +0.0136 | 0.0102 |
| 块 ×8 | +0.0036 | 0.0103 |

单遍已经与现役差 1e-4（M3.3 的同帧反作用起了作用），但 4 遍与 8 遍震荡 ⇒ 现在的代码
**钳到一遍**（`apply_block_cloth` 的 `iters.min(1)`），测试钉住"4/8 遍与 1 遍完全一致"。
"开多遍" = 把下面三笔账补平。

## 2. 三笔没进账的量

1. **速度钳位**：`λ = min(λ_geom, λ_vel)`。被钳掉的那一份**不消穿透**，却在外面按
   `λ·(w_p+w_b)` 记成"已消掉" ⇒ 残余被**低估**，下一遍会再消一次已经不该消的量。
2. **位置 make-up**：`lam > lam_geom` 那一支写 `body.dx`/`body.disp`（只补位置不补速度）。
   它确实改变了穿透，但**不进 `applied`** ⇒ 残余被**高估**，下一遍会把已经补过的再补。
3. **摩擦**：`apply_body_friction` 把粒子沿切向挪，法向投影量不变，但**接触点法线/位置**变了。
   一遍内假设法线冻结是可以的（VBD 也这么假设），但多遍之间必须**显式**说清"法线每遍重新取否"。

## 3. 拆法

把 `ClothBodyExt::apply_body_hit` 拆成三个可重入的段 + 一份逐接触账本：

```
solve(hit, ctx)   -> HitSolve { lam, lam_geom, lam_vel, v_point, make_up }
project(hit, s, h) -> 粒子法向推出 + 摩擦（只读 s）
reaction(hit, s, h, before) -> dv / disp / dx
closing(s)        -> 本遍**真正**消掉的穿透 = w_p·λ + w_b·λ [+ make-up 那一份]
```

- `closing` 是账本的唯一写入源；块循环用它更新 `applied[k]`，而不是在外面按 `λ·(w_p+w_b)` 猜。
- 三段**输入只读**（`ctx` 与 `s`），不读也不写 `self.body.dv/dx/disp` ⇒ 真可重入。
- 默认路径（遍数=0）照旧顺序调用三段，**逐位不变**（与 M3.2 的做法一致：先拆、后改语义）。

## 4. 判据（这就是这道题验收的标准）

1. **多遍收敛**：4 遍与 8 遍的盒末 y 差 ≤ `1e-3`（现在 1.0e-2、且非单调）。
2. **单遍不退化**：单遍与现役差 ≤ `1e-3`（现在 1e-4，不许变差）。
3. **默认档逐位不变**：`m4_cantilever` / `m4_flag` / `m4_rope` 三条金样 + determinism 10 轮全绿。
4. **多遍收益要有数**：若收敛后 4 遍的应变/穿透没有比 1 遍更好，就在文档里记**负结果**并继续钳一遍
   ——"多遍能跑通"不等于"多遍值得跑"。

## 5. 风险

- 拆三段会动 `cloth/ext/body.rs`（god 门按文件行数计）：三段 + 结构体大约 +80 行 ⇒ 先确认该文件在
  `god-baseline.json` 里的余额，不够就把三段搬进 `cloth/ext/body_hit.rs`。
- `ClothBodyExt` 是**扩展 trait**（`impl Trait for Type` 不计入类型成员账），所以拆出来的三段
  应挂在同一个 trait 上，别新建 inherent 方法（`ClothSheet` 的方法账只有 36→24 的硬阈余量）。
- 法线冻结假设：多遍之间不重取法线，与 VBD 论文一致；但要在文档里写明，否则会被当成缺陷。
