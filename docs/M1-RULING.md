# M1 刚体核心 · 性能档裁决（核口径）

> 出口判据（`ROUTE.md §7`）：**稳定 ✓ + 金样容差 ✓ + 性能档（SPEC §3）或核口径裁决**。
> 本文给出本机测得的成本结构，并回答"不走改写架构能不能达标"。

## 1. 本机实测（2026-10-30，`m1_pile` 10k 体、600 tick、单线程、release）

| 配方（iters / substeps） | 累计均值 ms/tick | 末态深穿透体 | 最大深度 |
|---|---|---|---|
| **16 / 1**（现行默认） | **72.8 – 81.9** | 4 – 75 | **0.714** |
| 16 / 4 | 353.9 – 406.6 | **0 – 10** | **0.008** |

两件事同时成立：

1. **子步把穿透压掉两个数量级**（0.714 → 0.008）——这正是 `DESIGN-staged-solver §7 缺陷①`
   说的"子步每遍 ≈ inner 的 4 倍价值"；
2. **但它贵 4.9×**（不是文档里 8B 场景的 1.84×，因为 10k 堆的接触更密）——因为
   `World::step` 每个子步都重跑宽相/窄相（缺陷②）。

⇒ **性能档的缺口不是解算器的算术量，是"每子步重跑碰撞检测"的固定成本。**

## 2. 三条已试过的路（都不通，别再走）

| 路 | 实测结论 | 出处 |
|---|---|---|
| 直接打开 `detect_once_per_tick()` | 金样 pile5 红 + **更慢 +29%**（保真退化让堆一直醒） | `impact.rs:34-42` |
| 准静态门（`max|v|·dt ≤ 0.5·skin`） | 门内复用会丢"深度/锚点按当前位姿重算"的细化 ⇒ 不可靠 | 同上 |
| (4,16,1) 便宜子步 | 2 个实锤：解算 −1/4，但**窄相 ×4 盖过收益** | `DESIGN-staged-solver §7 缺陷②` |

### 2026-10-30 追加：接触集**签名门**（试过，比旧门好，但**不优于现行默认**）

门从"速度阈值"换成"**连续两 tick 的接触集签名相同**（体对 + 点数 + 量化到 1e-4 的深度）+ 宽松速度兜底"。
签名是纯函数（顺序无关 / 方向无关 / 深度敏感 / 吸收 1e-5 抖动，4 条测试）。

| 场景 | 基线 | 签名门 | 判定 |
|---|---|---|---|
| col45 | — | 全过 | ✅ |
| **pile5** | 横向 0.0018 | **0.0012（−33%）** | 更好 |
| **tower25** | 横向 0.0165 | **0.0249（+51%）** | **更差**（仍在物理判据 ≤0.0260 内） |

入睡 / 超阈 / deep / Δpos **全部不变**，只有横向这一项、且两场景**方向相反**。

⇒ **裁决：不换代。** 拿 25 层塔的 51% 横向保真换 2000 体的 33% 收益不划算；
只重录 pile5 而让 tower25 一起变成 +51% 的记录，等于把退化静默改成"通过"。
⇒ 签名门**严格优于旧速度门**（旧门双输：入睡 1994/2000 + 慢 29%），但**不优于现行默认**。
真出路仍是下面 §3 的 ②/③（speculative contacts / 子步只重烘焙深度锚点）。

## 3. 裁决

**在"每子步重跑碰撞检测"这个架构下，性能档不可达，且与稳定性直接对冲**：
- 要稳定性 ⇒ 上子步 ⇒ 付 5× 检测成本；
- 要速度 ⇒ 单子步 ⇒ 最大深度 0.714（穿过 0.25 m 盒半厚的 ~3 倍）。

⇒ **M1 的性能档出口 = 改写"检测一 tick 一次、子步只重烘焙"这条管线**，三选一：
1. 门换成**接触集签名不变**（集合与几何都稳定才复用）；
2. **speculative contacts**（按一 tick 最大推进预生成接触，允许预测穿透）；
3. **子步只重烘焙深度/锚点**（几何复用、数值细化）。

任一落地前，**M1 按"稳定 ✓ + 金样 ✓ + 性能档未达（有裁决）"收口**，不冒充满分。

## 3.5 实测：tick 内**新接触点**比例（只读探针）

"复用接触集"唯一丢掉的是**tick 内新出现的接触点**（深度/锚点每子步都会按当前位姿重算）。
只读探针 `vxl_phys::world_step::contact_probe`（线程内、关闭时每子步只多一次原子读）：

| 场景 | 规模 | 新增点 / 观测点 | **比例** | 最差单 tick |
|---|---|---|---|---|
| tower25（25 层单柱） | 25 体 | 6,857 / 34,735 | **19.74%** | 22.50%（tick 43） |
| pile5（5 层 × 20²） | 2,000 体 | 1,224,984 / 7,662,759 | **15.99%** | 22.79%（tick 9） |
| 12 层塔（参照） | 12 体 | 3,796 / 17,241 | 22.02% | 23.15% |

复算：`cargo run --release -p vxl-phys --example contact_churn -- tower 25 120`（或 `pile 5 20 120`）。

**判读**：两个金样场景的 tick 内新点比例都在 **16–20%**，属常态 ⇒ 冻结接触集的代价与"新点比例"
成正比，`predict_dt` 调系数补不上（它只能把**已知**点看远，预测不了"会出现哪些新特征"）。
与签名门实测吻合：pile5（重复接触多）−33%、tower25（逐层新建接触）**+51%**。

⇒ 当时据此判"下一步只剩 swept speculative 候选生成"。**该判读已被 §3.6 的实测否证**
（漏掉的点几乎都不是"宽相没给候选对"，而是同一体对上的特征切换）。

## 3.6 实测：速度预测覆盖不了 churn（反事实探针，2026-10-31）

§3.5 只量"冻结接触集会丢多少新点"，没量**速度预测视野**（`set_predict_dt`：接受带从
`sep ≤ skin` 放宽为 `sep ≤ skin + max(0, 接近速度)·dt`）能把它们补回来多少。
做法：tick 首子步在**同一批候选对、同一速度、与真窄相同点（解算前）**再跑一趟
`predict_dt = 整 tick` 的窄相，结果**不喂解算器** ⇒ 动力学与不开探针逐位相同；
再与后续子步的真实流形比对。

复算：`cargo run --release -p vxl-phys --example contact_churn -- tower 25 120 --predict`
（`pile 5 20 120 --predict` 同理）。

### 3.6.1 预测覆盖率

| 场景 | 后续子步实点 | 首子步没有的新点 | **新点被预测覆盖** | 漏因：同对换特征 / 窄相视野拒收 / **宽相无候选** |
|---|---|---|---|---|
| tower25 | 34,735 | 10,300 | **1（0.01%）** | 10,243 / 56 / **0** |
| pile5 | 7,662,545 | 1,951,222 | **43,429（2.23%）** | 1,803,377 / 104,360 / **56** |

整份预测集里**投机点只有 2 / 51,589 个（0.0% / 2.0%）**：这两组场景里"按接近速度把接受带
放大一整 tick"几乎不产生新接触——体对要么不接近，要么早就接触了。

### 3.6.2 新点按位置再分（半径 = `max(2·skin, 1cm)`，即窄相点去重阈值）

| 场景 | 同体对·同位置换 ID | 同体对·真新位置 | 新体对 |
|---|---|---|---|
| tower25 | 6,705（65.1%） | 3,539（34.4%） | 56 |
| pile5 | 1,446,773（74.1%） | 399,236（20.5%） | 105,327 |

⇒ 按观测点算，冻结接触集**几何上真正丢掉**的是 **10.4%（tower25）/ 6.6%（pile5）**；
其余是同一位置上的特征 ID 翻转（旧点还在，深度/锚点按当前位姿重算 ⇒ 几何不丢，
丢的是 warm-start 的 ID 匹配）。

### 3.6.3 判读（撤回 §3.5 的"swept 候选对"结论）

1. **速度预测只覆盖新点的 0.01% / 2.23%** ⇒ 调 `predict_dt` 补回冻结接触集，不成立。
2. **宽相无候选对只有 0 / 56 条** ⇒ 扫掠宽相也补不上：体对早就在候选表里（fat 边距本来就是
   `|v|·dt·6`）。§3.5 的"只剩 swept speculative"**在本机读数上站不住**。
3. 主因是**特征切换**：65–74% 的新点是同体对、同位置、换了 feature ID；另有 20–34% 是同一体对
   上的真新位置。后者来自"窄相在该时刻还没接受这个特征"，扫掠体对解决不了。
4. ⇒ 下一步按性价比排序（先量再改）：
   a. **特征 ID 稳定性**：同一几何位置跨子步保持同一 feature ⇒ 冻结集的 warm start 才可能命中；
      这条对**现行默认档**（每子步重检测）也有独立价值，不依赖 M1 复用。
      **（§3.7 已按实测降级：回退分支本来就暖启动，ID 稳定化最多把 6–7% 的回退升级为精确。）**
   b. 每子步重烘焙详情（现行做法，不动）。
   c. swept 候选生成只在"新体对"上有限（tower 0.5% / pile 5.4%，且多数已在候选表里）⇒ 优先级最低。

⚠️ 口径边界：`predict_inflate` 只用**质心相对速度在法向的投影**（不含角速度，也不含切向运动
导致的换特征）⇒ "特征切换补不上"是**该实现的结论**，不是"任何预测都不可能"。

## 3.7 实测：warm「未匹配」是哪道门拒的（2026-10-31）

§3.6 之后的第一候选是"特征 ID 稳定性"。求解器本来就有跨帧匹配计数（`warm_match_stats_take`，
`EXPERIMENTS §K.1` 用过）：塔上 69.6% 精确 / 18.7% 回退 / 11.7% 未匹配；**回退那半已按位域拆过**
（78% 是"面选择变了"），**未匹配那半一直没有成因读数**。本轮补上：把回退分支的三道门做成**互斥**
归因（只计数、不改行为），读口 `vxl_phys_solver::warm_match::miss_gate_take()`。

| 场景（substeps=4、120 tick） | 精确 | 回退 | 未匹配 | 未匹配拒因：深度门 / 距离门 / 深度跳变门 |
|---|---|---|---|---|
| tower25 | 72.7% | 6.1% | 21.1% | 233（2.4%）/ **5,641（57.8%）** / 3,880（39.8%） |
| pile5 | 80.1% | 7.0% | 12.9% | **1,074,496（82.3%）** / 164,400（12.6%） / 66,207（5.1%） |

自校验：三桶之和 **精确等于**未匹配数（两场景都是；口径不一致会直接红）。

**判读**：

1. **塔的未匹配主因是距离门**（1×skin 内没有上一帧锚点 ⇒ 材料点真的换了位置/换了一组点），
   与 §3.6 的"同对真新位置 34.4%"同源。**放宽半径不是解法**——历史实测：放宽到 4×skin 会错配
   锚点 ⇒ 暖冲量过驱动 ⇒ 堆族永不入睡（`match_warm_point` 注）。
2. **堆的未匹配主因是深度门**（本帧 `depth ≤ 0`：已分离/投机接触不继承暖冲量）⇒ 这是**设计上的
   拒绝**，不是缺陷。
3. ⚠️ **"特征 ID 稳定化"因此降级**：回退分支**也暖启动**（只是锚点取近邻）⇒ ID 稳定化**不会**把
   任何"未匹配"变成命中，最多把 6–7% 的回退**升级为精确**；而未匹配的 21% / 12.9% 一分不动。
   ⇒ §3.6.3 的候选 a 上限很小，不足以支撑 M1 的性能档。
4. ⇒ 剩下的杠杆回到"**让检测本身更便宜**"（卡上窄相档 / SIMD）或"**接受 4 子步成本改核口径**"，
   两者都不是本轮读数能裁决的，需要单独立项 + A/B。

复算：`cargo run --release -p vxl-phys --example contact_churn -- tower 25 120`（末尾两行 `[warm]`）。

## 3.8 成本结构：4 子步里**求解占 83%**、检测只有 16%（"让检测更便宜"的天花板）

§3.6/§3.7 关掉了三条"少检测"的路（冻结复用 / 速度预测 / 特征 ID 稳定化）。剩下的假设 A 是
"**让检测本身更便宜**"。先量结构（工具只读，每档两遍顺序交错；引擎侧 `World::timings()`，ms/tick）：

```bash
cargo run --release -p vxl-phys --example substep_cost -- m1pile 120 3 1,4 8
```

| 10k 体 · iters=3 · threads=8 · 120 tick | wall | broad | narrow | solve | 检测合计 |
|---|---|---|---|---|---|
| substeps=1 | **47–50** | 5.4–6.0（12%） | 3.3–3.7（7%） | 36–38（76%） | 9.5（19%） |
| substeps=4 | **193–200** | 17.0–17.7（8.9%） | 13.8–14.2（7.2%） | **159–165（83.3%）** | 31（16%） |

（同一二进制连跑两遍；绝对毫秒有 ±10% 热漂移，**份额稳定**。）

**岛结构**（`w.solver.island_diag`）：ss=1 时 1364 岛 / 8 组；**ss=4 时 1 岛 / 1 组**（120 tick）；
300 tick 时回到 204 岛 / 8 组，但最大岛仍吃掉墙钟。**更硬的一条**：ss=1 那 8 组里，
**最大组占 99.3–99.5% 的墙钟与流形**（`group_us` / `group_manifs`）⇒ 密集堆的岛级并行是空转。

（求解内部三段 `build_us/warm_us/iter_us` 受 `ISLAND_SEG_PROBE` 门控、默认关 ⇒ 本读数里为 0；
要拆"构建 / 热启动 / 迭代"得单开一个诊断构建，本轮没做。）

**线程 × 子步**（60 tick、ss=4、1↔8 线程交错两轮）：narrow 62 → **17 ms（3.6×）**，
solve 162 → **169–197 ms（无收益、甚至更差）**。

**判读**：

1. **A 的上限 = 检测那一份**：8 线程 **16%**、单线程 34%。即使检测免费，ss=4 也只是
   193–200 → **162–169 ms/tick**，离 30 FPS（33 ms）仍差 **≈5×**。⇒ **A 不是主杠杆。**
2. 真正的瓶颈是**求解**：密集堆在 4 子步下几乎连成单岛 ⇒ 岛级并行拿不到；且求解量随子步
   **线性**涨（3 sweeps → 12 sweeps/帧）。
3. ⇒ 下一步该量的是"**求解能不能并行**"（岛内切分 / 图着色 / 接触级并行）与"**sweep 预算**"
   （A77 缺陷①：4×16×1 与 1×16×4 质量等同 ⇒ 每 sweep 的边际价值可能不同），而不是检测。
