# 布料 CPU 第一片：规则网格与三组 XPBD 距离约束

对应 `SPEC.md` §4.7，沿用绳索的子步、拉格朗日乘子清零及 `ProviderColliders` 接触口径。此片新增独立 `ClothSheet`，不改刚体/绳索的默认数值路径。

## 输入与边界

- `grid(origin, along_col, along_row, cols, rows)` 生成规则三角网：顶点行主序，稳定索引，三角面法线沿 `along_row × along_col`；两个方向的步长必须非零，行列至少为 2。调用方显式钉住节点；未钉住时为自由布片。
- 结构边连接水平/竖直邻点，剪切边连接每格两条对角线，弯曲边连接同一行/列相隔两点的节点。各组从 `ClothConstraints` 取独立 compliance；暂不启用其 `tear` 字段。
- 每子步按固定边序预测、投影三组边约束、投影静态 provider 接触、回写速度。拉格朗日乘子每子步清零，同一子步的迭代保留乘子。钉住的节点在积分和投影中不动。
- 网格三角形只是可供渲染/后续面元受力使用的拓扑；**不是** `Shape::TriMesh` 动态碰撞体。第一片未接 `World` 门面；第二片单独接入。没有布自碰撞、撕裂、面元气动力、刚体反作用、体积/面积守恒，不能把两片称作完整布料能力。

## 验收

1. 网格索引、三组边数、间距及钉扎行为准确；刚度档相互独立，改变一组不改变其他组的边配置。
2. 悬臂布在重力下下垂，钉住边不动；硬约束下拉伸残差有界，增加迭代后残差下降。
3. 自由布落在真实 `TriMesh` 地面上，不穿透；无 provider 的同场景继续下落，证明接触来自已有通道。
4. 同输入重复运行逐位一致；冻结第一片末态位置哈希。原有绳索与刚体冻结哈希不变。
5. 新示例输出顶点/三角形与悬垂末态数据，供后续可视化与面元力消费。

## 第二片：World 门面接线

- `World::add_cloth` 注册后可用 `cloth` / `cloths` 只读访问；每个 tick 在刚体子步、流体和绳索之后，按布料注册顺序推进一次完整 `config.dt`，布料内部自带子步。空集直接返回。绳索和布料归组进 `SoftDomain`，保持 `World` 类型成员棘轮不增长；既有绳索路径不变。
- 接触读取 `World::add_mesh` 注册的同一 `Providers` ID 空间；只读静态 provider，不与同场刚体发生接触/反作用。`World::state_hash()` 目前不包含布料（也不包含绳索）；门面测试单独按 `f32` 位模式冻结布料位置摘要，不应把刚体摘要当作完整场景摘要。
- `tests/cloth_scene.rs` 对照有/无地形、检查钉扎与下垂、同场刚体继续落地、两次同构造逐位一致，冻结两张布末态哈希。`cargo run -p vxl-phys --example cloth_world` 展示注册与只读状态访问。后续需增加自碰撞/面元力及其门面级判据，不能从此片推断已有动态 `Shape::TriMesh`。
